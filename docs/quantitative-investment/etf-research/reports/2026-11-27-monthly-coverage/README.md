# 独立 ETF 采集的月度覆盖

打开工作台「政策研究 → 月度数据覆盖」选择月份，或请求 `GET /api/v1/research/observation/monthly?month=YYYY-MM`。省略月份时用北京时间当前月。响应含逐日回执校验值、所用来源证据、来源缺口和连续未合格交易日。已封存月份固定显示首次通过核验的快照。开放月份显示本次读取时点的覆盖。

- 统计从独立采集启动日开始，分母取已到采集时间并经交易所日历核验的交易日。同一天的重试只增加回执数。手工采集回执单列。
- 五类覆盖分别计数，允许同一来源在重新抓取后首次取得证据。每项用来源的核验就绪时间与归档核验完成时间中的较晚值，和下一交易日北京时间 08:55 比较。日历未核实或来源证据未齐时保留相应缺口。
- 政策覆盖统计原文索引和候选的采集归档。政策审核、五日标签及实际模型入样进度在各自记录中核对。合格归档必须有一份完整的生产回执，跨次尝试的单来源结果只用于覆盖核对。
- Ubuntu 定时器北京时间 21:05 检查待封存月份。月份结束且最后一个应采交易日对应的下一交易日 08:55 已过，才生成固定快照。完整证据、缺口和实际计时一起封存。2026 年 11 月最后一个应采交易日为 11 月 30 日，首份快照最早在 12 月 1 日晚间生成。
- 封存验证检查来源快照的全部对象，绑定月报、采集回执及结果、日历和计算代码。恢复到新目录后可用同一归档库按 `asOf` 重算，旧回执和统计结果保留。缺件、损坏和新增实际记录分别显示。
- [11 月 27 日生产数据预览](live-preview.json)显示当时两类来源取得、三类待补证，属于月度实时进度。隔离验收另验证了两天连续缺口、盘前截止、晚到、历史时点、手工排除、封存后查验和从新目录重算。

只读复查及针对性验证命令如下。

```bash
PYTHONPATH=src python scripts/seal_observation_monthly.py --month 2026-11 \
  --observation-root "$observation_root" --archive-store "$archive_store"
PYTHONPATH=src python -m unittest discover -s tests -p test_observation_monthly.py -v
```
