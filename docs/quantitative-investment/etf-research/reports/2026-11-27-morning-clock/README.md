# 盘前决策、预测和开盘取证的定时时点

在 Ubuntu 创建一个隔离定时器，让同一个服务实际触发两次。北京时间 20:34:48 的首轮，进程变量与 systemd 管理器记录一致。20:35:15 的第二轮，进程变量仍指向 20:34:48，管理器给出第二次实际触发时间。两条记录的调用 ID 各自独立。 [两次系统日志](systemd-two-slots.json)

独立研究的 08:52 决策、08:53 预测及 09:26、09:28 开盘取证读取管理器记录，并核对已加载的日历时段与调用 ID。保留进程原始触发值和查询故障。决策与预测仍要求 08:55 前完成归档核验。开盘仍要求在各自分钟内开始，行情请求还要满足原有窗口、时间戳和报价核验。缺少时点证据时，开盘任务封存失败原因及零请求记录，标签保留证据缺口。

隔离验证用上一轮时间测试决策及预测会按新管理器证据正确判定，超时、测试任务和缺少时点证据的记录留在各自状态。开盘失败样例已从内容归档读回，并核对未发送行情请求。存量归档可按其已封存的触发字段复验。
