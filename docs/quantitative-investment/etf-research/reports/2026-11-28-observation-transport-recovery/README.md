# 盘前输入处理单个来源的无响应重试

盘前决策按各项依赖的实际收报和归档时点读取。最新一次采集对某个输入未取得 HTTP 响应时，允许从同一交易日紧邻的较早归档读取该输入的完整、已核验结果。只有该组其余依赖的查询地址一致、响应原文逐字节一致，且两次内容归档均通过复算，才启用复用。份额净值分别按基金核验；成交额与股票融资买入占比保留各自的完整依赖。政策审核的覆盖门槛照原协议执行。

复用只适用响应码为 0 且各重试的响应内容均为空的已记录传输中断。成功返回的空表、HTTP 404、依赖响应变化、归档受损、缺少早先完整证据都保持未知。该方法既保留旧值的实际收报时间，也仅在较晚失败归档已经核验后计入当前决策。决策回执绑定两次归档、原始时点和失败请求；看板「当日决策封存」和 Agent 当日 JSON 可查看同一字段。

## 实证与复算

北京时间 11 月 28 日 00:44，以 11 月 27 日为锚重放 11 月 30 日盘前输入，两个选取版本的实际输入值一致。真实归档可核验 9 项，沪市股票融资买入占比及政策计数仍留空。此次为提前验证，正式决策仍由系统定时封存。[真实时点复查](verification.json)

隔离演练以 11 月 27 日 22:23 的完整 ETF 份额和净值来源为基础。仅模拟 510300 净值请求未收到 HTTP 响应时，保留原股基输入并展示两次归档。分别使用 404、依赖字节变化和归档对象损坏复查，影响字段均留空。11 月 27 日的生产台账没有加入这些模拟事件。

新封存的盘前输入记录回放版本。旧记录仍使用原回放口径。命令行验证按文件中记录的版本复算；另行探查可向 `scripts/observation_inputs.py --entry ...` 增加 `--recover-transport`。
