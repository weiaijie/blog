# 前瞻证据存储容量巡检

12 个月独立研究和 24 个月模拟账户要保留原件、失败记录和可恢复归档。11 月 28 日 13:04 在 Ubuntu 读取实际文件系统，五种证据用途共用一个文件系统，可用 19,503,566,848 字节（约 18.2 GiB），占用约 93%，可用 inode 为 8,826,847。容量会随主机上的其他任务变动，单次读数不足以估计长期剩余月数。

健康服务每 15 分钟读取前瞻模拟、独立采集、独立证据归档、增量导出和整库归档的容量，按共用磁盘合并，使用运行用户可用的空间和 inode。容量观测随原健康回执封存。「政策与市场研究 → 独立研究运行健康」和 Agent 的 `/api/v1/research/observation/runtime-health` 读取同一份回执。测量失败按对应目录用途显示未知。

整库归档沿用已有的 100 MiB 保留量和对象大小检查。健康巡检将低于该保留量、容量耗尽或 inode 耗尽列为待核对，供运维处理。样本准入继续使用冻结协议中的原始证据、就绪和归档时点。

离线通过运行健康 5 项、归档恢复 15 项、前瞻账户健康 12 项和工作台 6 项测试，`systemd-analyze --user verify` 及 Vite 构建通过。测试涵盖同一卷合并、不同卷读数、低容量、inode 耗尽、目录缺失和旧回执读取。 [健康实现](../../scripts/observation_runtime_health.py) · [巡检配置](../../deploy/etf-research-health.service)

全量回归通过 507 项。完整性测试与项目校验脚本共用静态清单入口。首轮回归中，Ubuntu 默认 `/tmp` 的配额限制了行情测试的临时数据复制。改用项目验证盘上的独立临时目录重跑通过。

Ubuntu 发布后于 13:06 收到 systemd 健康回执，接口读回可用 18.2 GiB、已用 93%、可用 inode 8,826,798，十项研究调度无异常。1440 像素桌面与 390 像素手机的容量读数和 Agent 一致。部署初次替换静态清单时，新入口脚本曾返回 404。重启看板服务重载清单后页面、脚本和接口均返回 HTTP 200，已在运维手册补记顺序。

13:15 的计划触发于 13:15:01 成功结束。API 与封存回执读回一致，可用 19,449,630,720 字节、8,826,162 个 inode，问题项为空。健康回执清单 SHA256 为 `6c13a3ff18db8cdcf3003873721568ad56ad1afc698103dffdbb2f246c6090e1`。

使用运行模块逐一核验 16 份独立归档（1,953 项文件引用），最近一次整库归档的 17,240 个文件通过完整性核验。运行副本的归档清单现已覆盖 22 个在用工作台文件，旧构建仍保留。 [部署与恢复手册](../../docs/OPERATIONS_CLOSURE.md#独立研究运行目录)
