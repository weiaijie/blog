# 原账户整库归档的清单压缩

原 18 户每日整库归档保存一份完整文件清单，随历史记录增多而增长。新归档在内容寻址存储中使用 gzip 保存清单。SHA256 仍取解压后的标准 JSON 原字节，快照 ID、文件内容和对象校验口径延续。文件名在压缩流落盘后独占发布，先于归档状态回执。旧 `.json` 文件保留，原有 `verify`、`restore` 和 `compare` 可读取两种形式。

11 月 28 日 02:27 用实际生产快照的 16,883 条文件记录复核。清单从 3,162,555 字节降至 619,536 字节，节省 **80.41%**。解压结果与原清单逐字节相同，两个形式从同一对象集合独立通过完整核验。写压缩清单耗时约 0.085 秒。[测试数据与快照哈希](verification.json)

压缩收益的统计范围是新建的整库清单。对象存储增长、每日全量读取耗时和独立研究证据包继续分别观察。本轮时点主机剩余约 19.9 GB。新增清单损坏、哈希变化及发布中断已覆盖回归。[归档运行与恢复手册](../../docs/OPERATIONS_CLOSURE.md)
