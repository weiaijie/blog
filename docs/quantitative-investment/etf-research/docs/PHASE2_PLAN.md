# 下一阶段工程目标（2026-11-06启动）

本目标跨三个阶段，不能以单日行情更新、局部测试或一次提交结束。长期收益观察另行持续，不宣称本阶段证明4%～5%可行。

## 阶段一：独立执行对照

- 隔离Backtrader依赖与实现；不修改冻结引擎、协议、目标或旧结果。
- 固定样例覆盖分红登记/除息/支付/可用（含非交易日）、T+0/T+1、整手、无卖空、费用与卖税、刻度与不利滑点、现金边界、先卖后买、延迟、除息日/9%缓冲/缺失拒绝。
- 原生Backtrader Broker负责交易现金和持仓；适配层负责ETF特有事件和规则。不得把调用原Ledger包装成独立引擎。
- 第一层固定冻结目标，核对独立执行；共享目标不代表独立信号生成。162场景按日比较订单、拒绝、现金、应收、持仓与净值，记录全部差异和数值容差。
- 明确默认日线高低价撮合与冻结成本模型的区别，不能悄悄裁剪成交价。以证据决定候选替代范围，不要求为了迁移强行一致。

## 阶段二：风险研究

- Beta使用明确的基准、窗口、收益定义和最低样本数；历史与前瞻分开。
- 先固定压力情景，再计算当前暴露的损益；不根据结果选择有利压力值，不把冲击估算当预测。
- 持仓穿透仅使用可追溯官方披露，注明日期、披露覆盖与未知比例；不能将前十大当完整持仓、不能回填成历史持仓。

## 阶段三：每日流程

- 一条入口完成采集、证据核验、前瞻续接、对账、监控/页面输出与审计。
- 验证来源失败、公告变化、哈希冲突、重复执行、部分写入和恢复；旧快照、检查点及目标不可覆盖。
- Ubuntu定时运行方案及受控试运行，无实盘、无凭据提交；外部消息发送须另有明确授权和目的地。
- 自动采集不等于自动准入，失败应留痕而不是继续更新。
