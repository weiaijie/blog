# 稳定路线定制执行手册（个人版）

## 1. 使用说明

这份手册是对《稳定路线深度研究》的落地版，目标是让你每周有动作、每月有产出、每季度有证据。

适配对象（默认画像）：
- 30岁左右
- 已有技术基础
- 希望在组织内长期升级，不走创业高波动路线

如果你岗位与默认画像不同，把文中“后端模块/项目Owner”替换成你当前方向即可（前端、测试、数据、平台同样适用）。

---

## 2. 你的目标树（10年 -> 3年 -> 1年）

## 10年目标（方向）

成为组织内“关键技术责任人”，具备：
- 复杂系统治理能力
- 关键项目交付控制能力
- 技术决策与标准制定能力

## 3年目标（阶段）

1. 第1年：模块负责人（稳住质量）
2. 第2年：项目技术Owner（稳住交付）
3. 第3年：技术决策层预备（稳住方向）

## 1年目标（结果）

1. 至少主导 `2` 个中等复杂项目的技术交付
2. 输出 `8-12` 份高质量设计/复盘文档
3. 明显改善 `1-2` 个核心质量指标（例如回滚率/MTTR/P95）
4. 带出 `1-2` 名能独立交付子模块的同事

---

## 3. 岗位定制KPI（建议初版）

可直接用于你个人月度复盘，后续按团队实际阈值微调。

1. 质量类
- P1/P2事故（月）: 目标 `<=1`
- 发布回滚率（月）: 目标 `<5%`
- 缺陷逃逸率（月）: 环比下降或稳定低位

2. 效能类
- 核心需求准时交付率（月）: 目标 `>=90%`
- 关键任务一次通过率（月）: 目标 `>=80%`

3. 稳定性类
- 核心接口P95：持续在SLO以内
- MTTR：季度环比下降

4. 影响力类
- 主导技术评审（季）: `>=3`
- 跨团队协作项目（半年）: `>=2`
- 标准/规范落地（季）: `>=1`

5. 人才杠杆类
- 带教对象独立交付（半年）: `>=1`

## 4. 年度节奏（按季度执行）

## Q1：打地基（模块可控）

目标：
- 完成模块全景梳理
- 建立监控与风险基线
- 做1次质量改造闭环

必交付：
- 模块架构图 + 依赖图
- 风险清单V1
- 1份ADR + 1份复盘

## Q2：升责任（项目可控）

目标：
- 担任至少1个项目技术Owner
- 能做任务拆分、风险预判、节奏控制

必交付：
- 项目计划书（里程碑/风险/预案）
- 周报机制
- 1份项目复盘

## Q3：扩影响（跨团队可控）

目标：
- 推动1项跨团队技术标准或平台能力
- 建立“技术动作 -> 业务结果”表达能力

必交付：
- 标准文档V1
- 标准落地清单
- 管理层汇报材料1份

## Q4：收证据（晋升可控）

目标：
- 形成全年能力证据包
- 完成下一年角色升级谈判

必交付：
- 年度能力升级报告
- 绩效/晋升陈述稿
- 下年度路线图

## 5. 每周执行面板（固定节奏）

每周固定4个动作：

1. 系统治理（90分钟）
- 架构边界、技术债、稳定性改造三选一。

2. 风险巡检（30分钟）
- 看错误率、慢查询、容量、告警噪音。

3. 证据沉淀（30分钟）
- 记录本周关键决策和结果数据。

4. 对上同步（15分钟）
- 用四段式：问题、动作、结果、风险。

## 6. 你的“角色升级检查表”

## 从执行者 -> 模块负责人

- [ ] 能独立设计并解释模块边界  
- [ ] 能把线上问题闭环到机制层  
- [ ] 团队在关键问题上会主动征询你的方案

## 从模块负责人 -> 项目Owner

- [ ] 能拆分复杂项目并管理依赖  
- [ ] 能识别风险并提前提出预案  
- [ ] 能稳定控制范围、质量、节奏

## 从项目Owner -> 决策层预备

- [ ] 能定义跨项目标准  
- [ ] 能把技术指标翻译成业务收益  
- [ ] 能培养接班人，不被锁死在执行位

## 7. 晋升/绩效沟通脚本（可直接套用）

## 开场（定位）

过去一年我主要做了三件事：  
1) 把某模块从“可运行”提升到“可控”；  
2) 把项目交付从“按人推进”变成“按机制推进”；  
3) 把经验沉淀为可复用标准，降低团队重复犯错成本。

## 中段（证据）

关键证据有三类：  
1) 结果类：事故数、回滚率、P95、交付达成率；  
2) 机制类：ADR、Runbook、标准化文档；  
3) 组织类：跨团队项目、带教产出、方案采纳率。

## 结尾（诉求）

基于上述结果，我希望在下一周期承担更高责任边界：  
从模块负责升级到项目Owner/从项目Owner升级到技术决策预备，并绑定对应目标与评估标准。

---

## 8. 风险预案（出现偏航时怎么拉回）

1. 连续两个月事故偏高
- 立即冻结新增非必要复杂度
- 集中做“止血改造 + 监控补齐”

2. 长期被临时需求打断
- 固定“系统治理时段”上日历
- 对外明确容量上限和优先级机制

3. 做了很多但不可见
- 每周同步结果，每月提交证据包
- 把技术收益翻译成业务语言

4. 陷入纯执行
- 主动申请评审主讲、技术选型、风险评估责任

## 9. 未来90天任务板（你可直接照抄到任务系统）

## 第2个月

- [ ] 主讲1次技术评审  
- [ ] 输出1份事故复盘或演练复盘  
- [ ] 与上级做半小时目标对齐

## 第3个月

- [ ] 牵头1个小型跨团队需求  
- [ ] 输出项目计划书（里程碑+风险+预案）  
- [ ] 完成第一版能力证据包  
- [ ] 明确下季度Owner级目标

---

## 10. 最终执行原则

1. 每周都要有“系统性工作”，不能全是救火。  
2. 每月都要有“可证明成果”，不能只有忙碌感。  
3. 每季度都要有“角色升级动作”，不能只做原地优化。  
4. 每年都要有“证据包”，确保内部晋升与外部议价都成立。
