# 数字分身开源调研与自动分析方案

调研日期：2026-09-17。范围：GitHub 官方仓库、项目文档与论文；未安装或运行这些项目，未向外部服务上传聊天记录。

## 先纠正当前方向

用户希望通过已有聊天记录自动分析本人在工作、闲聊及其他状态下的回复方式。让用户逐条填写对象、意图并批准之后才能推进，是之前方案的偏差。历史真实回复已经是学习目标，离线整理并不需要用户重新讲一遍当时想说什么。

后续主流程改为自动构建数据、语义分析、生成对照和 AI 初评。页面用于查看结果与可选纠错；本人反馈能改善效果，但不再是启动分析的前置条件。未知关系可以保持未知，不能阻止已能确定的工作/闲聊场景分析。

## 查到的项目

| 项目 | 已核验做法 | 对当前项目的价值及限制 |
|---|---|---|
| [WeClone](https://github.com/xming521/WeClone) | 聊天预处理、数据清洗、LoRA 微调与推理；支持 LLM 为数据质量打分 | 最接近从聊天记录学习表达。适合借鉴数据管线；不是下载即可适配现有 CSV，训练环境和数据转换仍需处理 |
| [digital-twin-skill](https://github.com/FredHJC/digital-twin-skill) | 自动提取行为，合成共通特征与不同关系下的差异 | 很贴近工作/生活模式区分；是提示词与脚本方案，效果声明不是我们的实测结果 |
| [ChatHaruhi](https://github.com/LC1332/Chat-Haruhi-Suzumiya) | 角色提示、相似历史片段检索、当前对话历史一起生成 | 可借鉴检索相似场景示例；原项目主要面向虚构角色，不能直接声称会像用户本人 |
| [Second Me](https://github.com/mindverse/Second-Me) | README 描述分层记忆、个人模型训练和角色切换 | 适合更完整的个人知识与分身方向；本轮只核验官方介绍，未审计整条训练和记忆实现 |

### WeClone：自动构造样本，不要求逐条写意图

[预处理文档](https://docs.weclone.love/zh/docs/deploy/data_preprocessing.html)说明：按时间窗口合并连续消息、匹配问答对、做隐私过滤，可选本地或在线模型评分。[配置模板](https://github.com/xming521/WeClone/blob/cf0f1652e0ff3e5b951489b4ef33bca031eed19a/settings.template.jsonc)中连续消息窗口为 2 分钟，问答窗口 5 分钟，清洗开关默认关闭，不能把可选功能说成默认已跑。

核验[清洗实现](https://github.com/xming521/WeClone/blob/cf0f1652e0ff3e5b951489b4ef33bca031eed19a/weclone/data/clean/strategies.py)：对问答进行模型打分后按阈值筛选。本地与在线路径均存在；全部过滤或清洗出错时会回退原数据。我们不应照搬这个回退，失败数据应隔离。

### digital-twin-skill：稳定特征和场景差异分开

核验[行为提取提示](https://github.com/FredHJC/digital-twin-skill/blob/85ff9befd02ed556241d43a3e3d2f999aa1a4436/prompts/behavioral_extraction.md)与[合成提示](https://github.com/FredHJC/digital-twin-skill/blob/85ff9befd02ed556241d43a3e3d2f999aa1a4436/prompts/twin_synthesizer.md)：前者抽取语气、词汇、话题边界和行为；后者分两遍生成共通特征与各场景相对于共通特征的差异，并给少数据情况加低置信度说明。

其关系标签仍是输入，不能据此宣称它会自动准确识别所有社会关系。对我们更合适的是先按对话内容推断工作、闲聊、生活事务等场景，关系未知照常处理。提示中的模式示例不能当成用户真实特征；“永不泄露”等 README 承诺也不能视为技术保证。

### ChatHaruhi：用相似历史支撑生成

核验[ChatHaruhi.py](https://github.com/LC1332/Chat-Haruhi-Suzumiya/blob/290bf4ad22076156083804013012847a77c0646c/ChatHaruhi2.0/ChatHaruhi/ChatHaruhi.py)：`chat` 加载角色提示、调用 `add_story` 检索片段、加入对话历史，再请求模型。此结构可以借鉴为“本人风格 + 当前场景规则 + 相似历史对话 + 当前上下文”。[论文](https://arxiv.org/abs/2308.09597)报告自动和人工角色扮演评估，但不能迁移为本项目的准确率。

## 当前建议：先自动提取与检索，再评估是否微调

这是结合现有资料提出的实现选择，不是任何项目已保证对用户有效。

1. 从已有清洗 CSV 按会话、时间间隔和话题组织对话段，保留本人连续短消息、其他发送者和媒体缺失标记。不要只截几条又让用户补背景。
2. 在提取风格之前划分开发和留出评测数据，隔离相邻、重复片段，避免答案泄露。测试对话不能同时进入风格归纳或检索示例库。
3. 自动进行隐私过滤与语义质量判断，不局限于当前关键词匹配。缺失背景时扩大前文仍不能解决的样本标为不足，不交给用户批量填表。
4. 对开发集完整对话自动分析场景、本人可观察的回应状态、语气和句式，保存依据与置信度。历史归纳可看真实回复；预测评测时场景和状态只能从回复前的信息判断。
5. 汇总共通表达规则，再分别生成工作、闲聊、生活事务等风格说明；状态作为动态附加信息。数据少的场景不制造结论。
6. 自动构建“回复前上下文 → 本人真实回复”的回放评测。默认不要求 intent；若从答案概括意图，则另列为答案辅助的改写试验，不能混为自主模拟成绩。
7. 先用相似历史片段与风格规则生成草稿，AI 比较场景吻合、语言习惯、内容是否有依据；输出自动评价及不确定原因。本人可以抽看和纠错，不能把 AI 评分写成本人评分。
8. 如果检索与提示仍难以稳定保留表达习惯，再按 WeClone 路线做训练实验。Linux 环境使用独立 Ubuntu，不采用其文档提到的 WSL 路线。

2026-09-17 已实施新增的 `auto_lab.py` 自动路径，保留旧人工路径，不将人工批准标志全部改为 true。40 段候选由当前会话 AI 分析，15 段用于学习，13 段已先生成再揭示原回复并完成 AI 自评；12 段上下文不足单列。每条有场景、本人状态及前文依据。

已形成共通风格与分场景档案，并新增仅检索开发组的请求构建入口。检索目前是中文双字片段和英文词重合，不是语义向量。首轮结果尚不够像本人，主要问题是复述过多、追问不够具体和遗漏协作依赖。下一项是扩大非工作场景证据，用新的留出样本验证改进；不是等待用户填表。
