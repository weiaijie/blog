# Step 09: 验收、压测与上线门槛

## 目标

在上线前用可量化标准验证系统可靠性、性能和可恢复性。

## 功能验收

1. 正常流程：CLI 完成 + 自动化完成 + artifact 完成 + run.completed。
2. CLI 提前结束：自动化继续执行并最终完成。
3. CLI 静默：状态正确变为 `AI_IDLE`，非失败。
4. Runner 掉线：超过 `T_dead` 显示 `RUNNER_OFFLINE`。
5. Runner 恢复：spool 补传后状态恢复并可终态收敛。

## 稳定性验收

- 断网 1~3 分钟后自动恢复，事件不丢。
- 人工 kill Runner 后重启，run 不出现双终态。
- artifact 上传失败重试与补偿链路生效。

## 性能指标建议

- 监控延迟（P95）`<= 3s`
- 事件写入成功率 `>= 99.9%`
- 重放成功率 `>= 99.99%`
- 前端状态误判率 `< 0.5%`

## 上线门槛

- 必须通过上述功能与稳定性用例。
- 必须具备告警与可追溯审计。
- 必须明确回滚方案：
  - 关闭新 run 入口
  - 保留查询与导出
  - 离线补传未入库事件

## 交付清单

- 测试报告（含失败样本与证据）
- 运行手册（告警处理与恢复 SOP）
- 版本发布说明（变更点与风险）
