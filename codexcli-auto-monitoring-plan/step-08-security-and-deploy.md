# Step 08: 安全基线与部署方案

## 目标

在可运营前提下控制权限、密钥、数据泄露与隔离风险。

## 安全基线

1. 最小权限执行：
   - 默认只读
   - 按需启用 `--full-auto`
   - 高权限运行只允许在隔离环境
2. 密钥管理：
   - 禁止硬编码 `CODEX_API_KEY`
   - 统一由 Secret Manager/CI Secret 注入
3. 日志脱敏：
   - 对命令输出做 token/密钥模式过滤
   - 截图敏感区域打码（如账号、工号、手机号）
4. 审计留痕：
   - 谁触发 run
   - 使用了哪些权限
   - 哪些步骤失败并如何恢复

## 部署建议

- Runner：部署在 CI Runner 或专用执行机，网络出入口可控。
- API：提供事件摄取、心跳、状态查询、SSE。
- 存储：对象存储 + 关系数据库（事件索引与 run 元信息）。
- 前端：以 SSE 为主，WebSocket 作为控制通道可选。

## 平台兼容建议（WSL + macOS）

1. WSL2
   - 使用 Ubuntu 发行版，Runner 与浏览器依赖都安装在 WSL 内。
   - 避免将高频读写目录放在 `/mnt/c`，优先放在 Linux 文件系统。
   - CI 与本地保持同版本 Node/Python，避免 Playwright 浏览器驱动漂移。
2. macOS
   - 统一用 `bash` 或 `zsh` 启动 Runner，避免 shell 差异导致 env 丢失。
   - Apple Silicon 机器固定依赖版本，避免原生模块编译差异。
   - Playwright 浏览器缓存目录与 artifact 目录分离，便于清理和归档。

## 验收标准

- 关键密钥不会出现在普通日志。
- 任何高权限 run 都能被审计追溯。
