# 00 基线任务

## 0.1 版本范围与优先级

- [ ] 锁定 V1 范围：首页、关于我、技能、项目、联系方式。
- [ ] 锁定 V2 范围：博客列表/详情/标签/搜索 + 互动能力。
- [ ] 锁定 V3 范围：自建后端/CMS/账号体系。
- [ ] 为所有任务加标签：`v1`、`v2`、`v3`、`blocked`、`optional`。
- [ ] 所有超范围需求进入 backlog，不进入当前实现。

产出物：
- V1/V2/V3 范围表。
- 按优先级排序的 backlog。

验收标准：
- 同一任务不跨两个版本。

## 0.2 技术与部署基线

- [ ] 锁定技术栈：React + TypeScript + Vite + Tailwind。
- [ ] 锁定规范工具：ESLint + Prettier。
- [ ] 锁定托管方式：GitHub Pages。
- [ ] 锁定 CI/CD：GitHub Actions 构建与发布。
- [ ] 确定 V1 第三方服务（表单/统计/评论）。

产出物：
- 基线决策记录（1份 Markdown）。
- CI 工作流初稿。

验收标准：
- V1 实施票据中不再出现“或/可选”作为默认方案。

## 0.3 冲突处理规则

- [ ] 明确规则：静态优先，动态能力优先托管服务。
- [ ] 明确规则：新增动态需求必须附带可落地实现路径。
- [ ] 明确规则：候选方案只保留一个默认可执行方案。
- [ ] 定义冲突升级路径（负责人 + 响应时限）。

产出物：
- 冲突决策清单。

验收标准：
- 每个阻塞项都能映射到明确责任人。

## 0.4 完成定义（DoD）

- [ ] 页面 DoD：移动端与桌面端布局通过。
- [ ] 功能 DoD：导航/跳转/表单/筛选可用。
- [ ] 质量 DoD：无阻塞性控制台错误。
- [ ] 性能 DoD：Lighthouse Performance >= 80（移动端）。
- [ ] 可访问性 DoD：Lighthouse Accessibility >= 90。
- [ ] 内容 DoD：无占位文案、无 404。

产出物：
- DoD 通用检查模板。

验收标准：
- 页面任务勾选完成前必须通过 DoD。
