# 09 玩法规则规格表

本文件只定义第一版 30 回合 Web 原型的可实现规则。目标不是复刻完整《文明》，而是用足够小的规则集合验证：探索、建城、发展、研究、战争和胜利赛跑是否能形成持续选择。

## 一、玩法目标

| 项目 | 第一版规格 |
| --- | --- |
| 原型局长 | 30 回合 |
| 单局时长 | 20-40 分钟 |
| 玩家数量 | 1 名玩家 + 1 个 AI |
| 地图尺寸 | 默认 16x16，允许 12x12 到 20x20 |
| 地图形态 | 第一版使用方格；六边形作为第二版替换项 |
| 城市上限 | 每方最多 3 座城市 |
| 单位上限 | 每方最多 10 个单位 |
| 核心资源 | 粮食、生产力、金币、科技 |
| 核心路线 | 扩张发展、军事压制、科技竞速 |
| 胜利方式 | 征服胜利、科技胜利、30 回合分数胜利 |
| 设计目标 | 玩家每回合至少有一个明确选择，并能看懂收益、代价和失败原因 |

### 第一版范围裁决

| 争议项 | 第一版裁决 |
| --- | --- |
| 地图形态 | 第一版固定方格；六边形只作为第二版迁移目标。 |
| 外交交易 | 第一版不做主动外交交易、停战谈判、同盟或议和。 |
| 贸易路线 | 第一版“贸易”只作为科技和市场带来的被动经济加成，不创建 `CREATE_TRADE_ROUTE` Command。 |
| 科技胜利项目 | `天文台计划` 是全局 `ResearchProject`，消耗全局科技，不占城市生产队列。 |

## 二、单回合流程

本表遵循 [08_工程架构设计.md](./08_工程架构设计.md) 的唯一权威回合状态机。

| 顺序 | 阶段 | 规则 | 产出日志 |
| --- | --- | --- | --- |
| 1 | `PLAYER_ACTION` | 玩家移动单位、选择生产、选择科技、建城、攻击、查看外交。 | 记录成功 `RuleCommand` 和即时结果。 |
| 2 | `PLAYER_END` | 若有未选择科技、空生产队列、可行动单位，UI 提醒但允许强制结束。 | 提醒未处理事项，锁定玩家规则输入。 |
| 3 | `AI_PLAN` | AI 基于玩家行动后的当前状态选择研究、生产、移动、扩张、攻击。第一版可主线程执行，但走 WorkerLike 协议。 | 记录 AI 当前意图、候选评分、耗时。 |
| 4 | `AI_ACTION` | 主线程逐条验证并执行 AI `RuleCommand`，非法命令被拒绝并记录。 | 记录 AI 行动、失败原因、回退动作。 |
| 5 | `TURN_RESOLVE` | 对所有玩家按固定顺序结算城市产出、人口成长、生产、科技、维护费、单位状态。 | 输出资源、人口、生产、科技、维护日志。 |
| 6 | `WORLD_RESOLVE` | 更新战争迷雾，检查征服胜利、科技胜利和第 30 回合分数结算。 | 输出视野变化、胜利进度、终局事件。 |
| 7 | `AUTOSAVE` | 在完整稳定状态上保存 `autosave_latest`。 | 自动存档成功/失败。 |
| 8 | `NEXT_TURN` | 回合数 +1，进入下一回合玩家行动阶段。 | 第 N+1 回合开始。 |

## 三、地图与地形规则

| 地形 | 基础产出 | 移动力消耗 | 防御加成 | 是否可建城 | 是否可通行 | 设计用途 |
| --- | --- | ---: | ---: | --- | --- | --- |
| 平原 | 粮食 +2，生产力 +1 | 1 | 0% | 是 | 是 | 基础发展地块，适合早期城市。 |
| 森林 | 粮食 +1，生产力 +2 | 2 | +15% | 是 | 是 | 提供生产和防御，但移动较慢。 |
| 丘陵 | 粮食 +1，生产力 +2 | 2 | +25% | 是 | 是 | 生产和防御强，适合边境城市。 |
| 河流 | 地块附加金币 +1 | 不额外增加 | 0% | 是 | 是 | 提高城市经济和选址价值。 |
| 山脉 | 科技 +1 | 不可通行 | +30% | 否 | 否 | 形成天然屏障和科技相邻奖励。 |
| 水域 | 粮食 +1，金币 +1 | 不可通行 | 0% | 否 | 否 | 第一版只作为地形边界，海军第二版再做。 |

| 地图规则 | 第一版规格 |
| --- | --- |
| 初始视野 | 玩家首都周围 3 格可见，其他区域为未探索。 |
| 单位视野 | 侦察兵 3 格，其他单位 2 格，城市 3 格。 |
| 战争迷雾 | 分为未探索、已探索不可见、当前可见三种状态。 |
| 资源生成 | 每个玩家首都 4 格内保证至少 1 个粮食优势点和 1 个生产优势点。 |
| 起始距离 | 玩家与 AI 首都距离至少 8 格，避免过早决战。 |
| 固定调试地图 | 必须保留一个固定种子地图，用于测试数值和复现 bug。 |
| 点击命中 | 第一版用 CPU 坐标换算命中格子，不做 GPU Picking。 |

## 四、城市规则

| 城市属性 | 初始值/公式 | 说明 |
| --- | --- | --- |
| 初始人口 | 1 | 首都和新城都从 1 人口开始。 |
| 初始生命值 | 30 | 城市可被攻击；生命值归零后被占领。 |
| 初始防御力 | 8 | 建造城墙后提升。 |
| 工作地块数量 | 等于人口数 | 每 1 人口自动工作 1 个范围内最佳地块。 |
| 城市范围 | 城市中心 2 格内 | 第一版不做文化扩张，建城即获得 2 格范围。 |
| 建城限制 | 两城之间至少间隔 4 格 | 防止城市过密。 |
| 城市上限 | 每方最多 3 座 | 控制 30 回合原型管理压力。 |
| 城市维护 | 每座非首都城市每回合金币 -1 | 让扩张有轻微代价。 |
| 距离维护 | 距首都超过 6 格的新城额外金币 -1 | 限制无脑远距离铺城。 |

| 建筑 | 成本 | 效果 | 前置科技 |
| --- | ---: | --- | --- |
| 粮仓 | 20 生产力 | 城市每回合粮食 +2，人口成长阈值 -10%。 | 无 |
| 工坊 | 25 生产力 | 城市每回合生产力 +2。 | 采矿 |
| 市场 | 25 生产力 | 城市每回合金币 +3。 | 贸易 |
| 学院 | 30 生产力 | 城市每回合科技 +3；相邻山脉额外科技 +1。 | 书写 |
| 城墙 | 30 生产力 | 城市生命值 +20，防御力 +5，受到远程伤害 -20%。 | 石工 |

## 五、人口与资源公式

| 资源 | 类型 | 主要来源 | 用途 |
| --- | --- | --- | --- |
| 粮食 | 城市局部 | 城市中心、工作地块、粮仓 | 人口成长 |
| 生产力 | 城市局部 | 城市中心、工作地块、工坊 | 建造单位和建筑 |
| 金币 | 全局 | 河流、市场、被动贸易加成、城市基础收入 | 维护费；外交交易和紧急购买第二版再做 |
| 科技 | 全局 | 人口、学院、山脉相邻加成 | 研究科技 |

| 公式 | 第一版规则 |
| --- | --- |
| 城市中心产出 | 每城固定粮食 +2、生产力 +1、金币 +1、科技 +1。 |
| 工作地块选择 | 自动选择该城范围内综合价值最高的 N 个地块，N = 人口。综合价值 = 粮食 + 生产力 + 金币 + 科技。 |
| 城市粮食收入 | 城市中心粮食 + 工作地块粮食 + 建筑粮食。 |
| 城市生产力收入 | 城市中心生产力 + 工作地块生产力 + 建筑生产力。 |
| 全局金币收入 | 所有城市金币收入 - 城市维护 - 单位维护。 |
| 全局科技收入 | 所有城市科技收入 + 人口科技加成。 |
| 人口科技加成 | 每个城市每 1 人口提供科技 +0.5，可在 UI 中四舍五入显示，但内部保留小数。 |
| 人口成长阈值 | 15 + 当前人口 x 8。建有粮仓时乘以 0.9。 |
| 生产溢出 | 项目完成后，剩余生产力保留到下一个项目。 |
| 金币为负惩罚 | 金币库存低于 0 时，所有城市生产力 -10%，直到金币回到 0 以上。 |

## 八、战斗结算

| 项目 | 第一版规则 |
| --- | --- |
| 基础伤害 | 伤害 = max(2, 攻击方攻击 - 防御加成后的防御值 / 2)。 |
| 防御值 | 单位防御值默认等于攻击值；城市使用城市防御力。 |
| 地形防御 | 森林 +15%，丘陵 +25%，城市 +20%，城墙额外减伤 20%。 |
| 近战反击 | 近战攻击会受到目标反击；反击伤害按目标攻击的 50% 计算。 |
| 远程反击 | 被弓手远程攻击的目标不反击。 |
| 单位死亡 | 生命值降到 0 时移除单位。 |
| 城市占领 | 城市生命值降到 0 后，必须由近战单位进入城市格才算占领。 |
| 占领首都 | 占领敌方首都立即触发征服胜利。 |
| 战斗日志 | 必须记录攻击方、目标、地形、防御加成、伤害、剩余生命值。 |

| 示例 | 计算 |
| --- | --- |
| 战士攻击平原侦察兵 | 战士攻击 8，侦察兵防御 4，伤害 = max(2, 8 - 4/2) = 6。 |
| 弓手攻击丘陵战士 | 战士防御 8 x 1.25 = 10，伤害 = max(2, 6 - 10/2) = 2。 |
| 战士攻击无城墙城市 | 城市防御 8 x 1.2 = 9.6，伤害约 3.2，内部保留小数或统一向下取整。 |

## 九、胜利条件与分数

| 胜利 | 触发条件 | UI 展示 |
| --- | --- | --- |
| 征服胜利 | 玩家占领 AI 首都，或 AI 占领玩家首都。 | 胜利进度显示双方首都状态、城市生命值、最近敌军距离。 |
| 科技胜利 | 完成科技“数学”后投入 80 科技完成“天文台计划”。 | 胜利进度显示当前科技项目完成百分比。 |
| 分数胜利 | 第 30 回合结束时无人达成征服或科技胜利。 | 复盘面板显示双方得分来源。 |

| 分数项 | 公式 |
| --- | --- |
| 城市 | 每座城市 20 分 |
| 人口 | 每 1 人口 5 分 |
| 科技 | 每完成 1 个科技 8 分 |
| 单位 | 每个存活单位 3 分 |
| 金币 | 每 10 金币 1 分，最多 20 分 |
| 敌方首都伤害 | 敌方首都每损失 10 点生命值 2 分 |
| 科技胜利进度 | 天文台计划每 10% 进度 3 分 |

## 十、30 回合节奏节点

| 回合 | 玩家体验目标 | 系统要求 | 观察指标 |
| --- | --- | --- | --- |
| 1 | 玩家看到首都、侦察兵、战士，并选择第一项科技。 | 教学提示移动、研究、生产、结束回合。 | 玩家是否能在 2 分钟内结束第一回合。 |
| 2-5 | 探索附近资源、理解地形产出和战争迷雾。 | 地块 Tooltip、可达范围、视野更新。 | 玩家是否主动比较资源地块。 |
| 6-8 | 首个生产项目完成，科技完成或接近完成。 | 生产完成弹窗、科技解锁提示。 | 玩家是否理解“为什么完成”。 |
| 9-12 | 玩家面临建造者、军事或建筑选择。 | 城市面板展示生产成本和收益。 | 玩家是否在扩张、军事、经济之间犹豫。 |
| 13-16 | 第二城或边境压力出现。 | 建城规则、维护费、AI 位置公开或半公开。 | 玩家是否理解扩张代价。 |
| 17-22 | 科技路线分化，军事或科研优势开始形成。 | 胜利进度面板、AI 意图显示。 | 玩家是否能说出自己当前路线。 |
| 23-26 | 出现第一次战略冲突或科技胜利压力。 | 战斗结算、城市防御、科技项目进度。 | 玩家是否开始针对 AI 行动。 |
| 27-30 | 进入终局判断，玩家冲刺征服或科技。 | 胜利检测、分数预览、复盘面板。 | 玩家是否知道自己为什么赢/输。 |

| 功能 | 第一版要求 |
| --- | --- |
| 前 5 分钟引导 | 依次引导移动侦察兵、查看地块产出、选择城市生产、选择科技、结束回合。 |

## 十二、第一版不做事项

| 不做内容 | 原因 | 后续方向 |
| --- | --- | --- |
| 完整外交 | UI、AI 和交易规则都会显著扩大范围。 | 第二版做关系值、交易、停战、结盟。 |
| 文化/制度树 | 会和科技树争夺注意力。 | 第二版增加政策和文明风格。 |
| 宗教系统 | 独立系统成本高。 | 视主题需要再加。 |
| 海军和海战 | 涉及新地图、寻路和单位规则。 | 第二版或第三版。 |
| 完整时代系统 | 会改变科技、单位、事件和美术。 | 第二版做时代章节。 |
| 多人 | 网络同步和一致性验证过重。 | 原型稳定后再评估。 |
| 复杂贸易市场 | 经济模型会快速膨胀。 | 第二版再评估主动贸易路线和市场。 |
| 大量文明和领袖 | 平衡成本高。 | 第一版最多用简单特性占位。 |
| 复杂地块改良 | 会增加建造者微操。 | 第二版再做农田、矿山、道路。 |
| 奇观系统 | 容易变成内容堆叠。 | 规则稳定后加 2-3 个测试奇观。 |

## 十三、实现验收清单

| 模块 | 验收标准 |
