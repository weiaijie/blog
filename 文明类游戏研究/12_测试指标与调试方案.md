# 12 测试指标与调试方案

本文档定义第一版 30 回合 Web 原型的测试、性能、试玩数据和调试工具方案。它承接现有决策：`TypeScript + Vite + PixiJS/WebGL + React DOM UI`，规则层由 `GameState + Command + Validator + Simulation` 独立负责，渲染层只读状态。

核心目标：让玩法规则可验证、回合结果可复现、浏览器体验不卡、玩家行为可观察、AI 决策可解释。

## 一、测试目标总览

| 目标 | 说明 | 第一版标准 |
| --- | --- | --- |
| 规则正确 | 地图、城市、资源、科技、单位、战斗、胜利按 09 文档公式运行。 | 核心规则都有自动化单测。 |
| 回放一致 | 同一初始 seed + 同一 CommandLog 得到同一 GameState。 | Debug Export 可复现指定局面。 |
| 浏览器可玩 | PixiJS 地图、React 面板、输入、存档、读档能在桌面浏览器稳定运行。 | Playwright 冒烟测试覆盖主流程。 |
| 性能可控 | 地图拖拽、缩放、结束回合、AI 决策不明显卡顿。 | 桌面 60 FPS 目标，低端 30 FPS 可接受。 |
| 数据可分析 | 能记录玩家是否理解第一回合、扩张、科技、战斗和胜利压力。 | 试玩埋点能导出 JSON/CSV。 |
| 调试高效 | 开发者能看到 GameState、EventLog、AI 意图、性能、坐标和存档。 | 第一版必须有 Debug Panel 和 Debug Export。 |

## 二、测试金字塔

| 层级 | 覆盖内容 | 工具建议 | 执行频率 | 失败影响 |
| --- | --- | --- | --- | --- |
| Simulation 单测 | 资源公式、移动、战斗、科技、胜利、Validator 错误码。 | Vitest / Jest | 每次提交、开发时频繁运行 | 必须修复，规则层不能带病进入 UI。 |
| 数据与回放测试 | GameState schema、CommandLog 重放、RNG 确定性、存档迁移。 | Vitest + 固定 fixture | 每次提交 | 必须修复，影响存档和复现。 |
| 集成测试 | CommandBus、Simulation、Storage、WorkerClient 边界。 | Vitest + fake IndexedDB + mock Worker | 每次提交 | 高优先级修复。 |
| 浏览器冒烟测试 | 开局、移动、选择科技、生产、结束回合、存档读档、调试面板。 | Playwright | 合并前、版本发布前 | 阻止发布。 |
| 性能测试 | FPS、frame time、结束回合耗时、AI 耗时、存档耗时、内存趋势。 | 浏览器 Performance API + 自建采样 | 每个试玩版本 | 超预算则进入优化清单。 |
| 人工试玩 | 教学节奏、信息透明、决策压力、胜负理解。 | 试玩问卷 + Debug Export | 每个里程碑 | 转化成规则/UI 调整任务。 |

## 三、Simulation 单测原则

| 原则 | 要求 |
| --- | --- |
| 不加载渲染 | Simulation 测试不能 import PixiJS、React 组件或 DOM。 |
| 纯数据输入 | 测试输入使用 `GameState` fixture、`Command`、固定 seed。 |
| 明确断言 | 断言新状态、事件日志、错误码，不只断言“没有报错”。 |
| 小局面测试 | 每个测试只构造最小地图和最少单位，便于定位失败原因。 |
| 随机可控 | 所有随机结果必须来自可记录 RNG，不允许直接调用 `Math.random()`。 |
| 失败可读 | 测试名称写成规则语言，例如“战士攻击丘陵战士时地形防御降低伤害”。 |

推荐目录：

```text
src/
  simulation/
    __tests__/
      resource.test.ts
      movement.test.ts
      combat.test.ts
      city.test.ts
      tech.test.ts
      victory.test.ts
      replay.test.ts
      validator.test.ts
  test-fixtures/
    maps/
    states/
    command-logs/
```

## 四、核心规则测试表

| 模块 | 测试点 | 输入 fixture | 期望结果 |
| --- | --- | --- | --- |
| 地图生成 | 固定 seed 生成固定 16x16 地图。 | `seed = debug-map-001` | 地形、资源、首都起点、起始距离完全一致。 |
| 视野 | 首都 3 格、侦察兵 3 格、战士 2 格视野更新。 | 玩家首都 + 两个单位 | `visibleBy` 与 `exploredBy` 正确区分。 |
| 移动 | 不同地形消耗移动力。 | 侦察兵从平原移动到森林/丘陵 | 平原扣 1，森林/丘陵扣 2，山脉/水域不可进入。 |
| 移动失败 | 移动力不足或目标阻挡。 | 战士剩余移动力 1，目标为森林 | Validator 返回 `NOT_ENOUGH_MOVEMENT`。 |
| 单位堆叠 | 每格最多 1 军事单位 + 1 建造者。 | 同格已有战士 | 第二个军事单位移动失败。 |
| 建城 | 建造者在合法地块建城。 | 建造者 + 可建城平原 | 城市创建，建造者消失，城市人口为 1。 |
| 建城失败 | 城市距离不足或城市上限。 | 已有 3 城或距离小于 4 | Validator 返回 `CITY_LIMIT_REACHED` 或距离错误。 |
| 城市产出 | 城市中心 + 工作地块 + 建筑。 | 2 人口城市 + 粮仓/工坊 | 粮食、生产力、金币、科技按公式增加。 |
| 人口成长 | 粮食库存达到阈值。 | 人口 2，粮食达到 `15 + 2 x 8` | 人口 +1，粮食扣除阈值。 |
| 金币惩罚 | 金币低于 0。 | 维护费大于收入 | 全城市生产力 -10%。 |
| 生产队列 | 生产完成和溢出。 | 城市生产力库存接近成本 | 项目完成，溢出进入下个项目。 |
| 科技研究 | 科技投入、切换和解锁。 | 科技收入 + 正在研究农业 | 成本达到后解锁粮仓。 |
| 科技前置 | 前置未完成。 | 直接研究战术 | Validator 返回 `TECH_PREREQ_MISSING`。 |
| 近战战斗 | 近战伤害和反击。 | 战士攻击侦察兵 | 双方生命值按公式变化，攻击方行动结束。 |
| 远程战斗 | 弓手射程 2，无反击。 | 弓手攻击战士 | 目标受伤，弓手不受反击。 |
| 地形防御 | 森林、丘陵、城市、城墙减伤。 | 同一攻击方攻击不同地形目标 | 丘陵目标伤害低于平原目标。 |
| 城市占领 | 城市生命值归零后近战进入。 | 战士攻击低血量城市 | 进入城市格后触发占领。 |
| 胜利检测 | 征服、科技、分数胜利。 | 三组接近胜利状态 | 触发对应胜利事件，胜利方正确。 |
| 回合流程 | 12 个回合阶段顺序。 | `END_TURN` | 单位刷新、AI、城市、科技、维护、视野、胜利按顺序记录。 |
| 日志 | 关键变化进入 EventLog。 | 生产完成、科技完成、战斗 | 日志包含对象 id、数值变化、原因。 |

## 五、回放一致性测试

| 测试 | 方法 | 验收标准 |
| --- | --- | --- |
| CommandLog 重放 | 从初始 `GameState` 逐条执行 CommandLog。 | 最终 `GameState` 与原局快照的规则字段一致。 |
| RNG 确定性 | 同 seed 执行同命令序列。 | 地图、战斗随机项、事件触发结果一致。 |
| 存档恢复 | 保存第 10 回合，读档后继续到第 30 回合。 | 与未中断连续执行结果一致。 |
| Debug Export 复现 | 导出 JSON 后在测试工具中导入重放。 | 能定位到失败回合、失败命令和状态差异。 |
| 版本迁移 | 旧 `schemaVersion` 存档迁移到当前版本。 | 迁移后能进入游戏，关键字段有默认值。 |

回放对比不应比较 PixiJS Sprite、React UI 展开状态、性能采样值和当前相机位置。必须比较地图、玩家、城市、单位、科技、外交、胜利、回合数、RNG 状态、成功 CommandLog。

## 六、浏览器冒烟测试

Playwright 冒烟测试用于确认 Web 原型可操作，不替代 Simulation 单测。

| 用例 | 操作步骤 | 验收标准 |
| --- | --- | --- |
| 首屏加载 | 打开本地开发地址。 | 画布非空，React UI 出现，默认 16x16 地图可见。 |
| 地图交互 | 拖拽地图、滚轮缩放、悬停地块。 | 相机移动顺滑，Tooltip 显示地形、产出、移动消耗。 |
| 选择单位 | 点击侦察兵或战士。 | 单位被选中，可达范围高亮，面板显示血量/移动力。 |
| 单位移动 | 选择可达地块移动。 | 单位位置变化，移动力扣除，EventLog 记录移动。 |
| 非法移动 | 尝试移动到山脉/水域或过远地块。 | 不改变状态，UI 显示明确失败原因。 |
| 城市面板 | 点击首都。 | 展示人口、粮食、生产队列、每回合产出。 |
| 生产选择 | 给首都选择侦察兵/粮仓。 | 队列更新，结束回合后生产进度增加。 |
| 科技选择 | 打开科技树选择农业/采矿。 | 科技状态更新，预计完成回合显示。 |
| 结束回合 | 点击结束回合或快捷键。 | 回合数增加，AI 意图日志出现，资源结算日志出现。 |
| 存档读档 | 保存当前局，刷新页面后读取。 | 回合数、单位位置、城市状态、科技进度恢复。 |
| 调试面板 | 打开 Debug Panel。 | 显示 FPS、frame time、GameState 摘要、AI 意图、坐标 overlay 开关。 |
| 复盘触发 | 使用 debug 命令跳到第 30 回合或触发胜利。 | 出现胜利/失败/分数复盘面板。 |

建议 Playwright 至少覆盖 Chromium。第一版可以暂不把 Safari/Firefox 作为阻断项，但需要人工抽查。

## 七、性能预算

| 指标 | 目标值 | 最低可接受 | 采样方式 | 触发动作 |
| --- | ---: | ---: | --- | --- |
| 平均 FPS | 60 | 30 | `requestAnimationFrame` 采样 10 秒滑动窗口 | 低于 30 进入优化。 |
| p95 frame time | 16.7ms | 33ms | 统计最近 600 帧 | 超过 33ms 标记卡顿。 |
| 首屏可交互时间 | 3s 内 | 5s 内 | `performance.mark` 从页面加载到地图可点 | 超过 5s 优化资源加载。 |
| 地图拖拽响应 | 无明显跳帧 | p95 低于 33ms | 拖拽期间单独采样 | 优化 culling/批处理。 |
| 滚轮缩放响应 | 100ms 内反馈 | 200ms 内 | 输入事件到下一帧绘制耗时 | 优化相机和渲染更新。 |
| 结束回合耗时 | 500ms 内 | 1000ms 内 | `END_TURN` command trace | 超过 1000ms 拆 Worker。 |
| AI 决策耗时 | 300ms 内 | 800ms 内 | AI plan trace | 超过 800ms 进入 Worker 或降复杂度。 |
| A* 寻路耗时 | 20ms 内 | 50ms 内 | 每次路径请求采样 | 超过 50ms 缓存或 Worker。 |
| 存档写入 | 200ms 内 | 500ms 内 | IndexedDB 写入耗时 | 超过 500ms 压缩/裁剪存档。 |
| 读档恢复 | 500ms 内 | 1000ms 内 | IndexedDB 读取 + hydrate | 超过 1000ms 优化迁移。 |
| 内存趋势 | 30 分钟稳定 | 不持续增长 | `performance.memory` 可用时采样 | 连续增长检查 Sprite/事件泄漏。 |
| 渲染对象数 | 可解释、可控 | 不随回合无界增长 | Debug Panel 统计 Sprite/Container 数 | 异常增长检查销毁逻辑。 |

第一版地图范围为 12x12 到 20x20，默认 16x16；每方最多 3 城、10 单位。性能指标先针对这个规模，不提前为大地图做过度优化。

## 八、性能采样方式

| 采样项 | 实现建议 | 展示位置 |
| --- | --- | --- |
| FPS / frame time | 每帧记录 `delta`，保留最近 600 帧，计算 avg/p50/p95/max。 | Debug Panel 顶部。 |
| Command trace | 每个 Command 记录 validate、simulate、renderSync、uiUpdate 耗时。 | Command Inspector。 |
| EndTurn trace | 分段记录 AI、城市结算、生产、科技、维护、视野、胜利检测。 | Turn Profiler。 |
| Render stats | 记录 tile sprite、unit sprite、overlay sprite、draw/update 次数。 | Render 页签。 |
| Worker stats | 记录 requestId、type、payload size、耗时、timeout、error。 | Worker 页签。 |
| Storage stats | 记录存档大小、写入耗时、读取耗时、schemaVersion。 | Storage 页签。 |
| Interaction latency | 记录 pointer down 到状态变化、状态变化到下一帧绘制。 | Input 页签。 |

采样数据默认只保存在内存中；手动 Debug Export 时写入导出文件。试玩版本如需要上传，应先匿名化，并明确告知试玩者。

### 性能测试实现入口

性能测试不能只靠人工感觉。第一版需要提供开发模式测试接口，供 Playwright 和 Debug Panel 调用。具体协议见 [25_压力测试矩阵与容量规划.md](./25_压力测试矩阵与容量规划.md) 的“浏览器实测调用规范”。

| 接口 | 用途 | 第一版要求 |
| --- | --- | --- |
| `window.__civPerf.loadScenario(id)` | 加载固定性能场景。 | 至少支持 `perf-default-16`、`perf-stress-20`、`perf-turn-30`。 |
| `window.__civPerf.startTrace(caseId)` | 开始记录 FPS、frame time、render stats、turn/storage trace。 | 必须。 |
| `window.__civPerf.stopTrace()` | 返回 `PerfTrace` JSON。 | 必须能被 Playwright 保存到 `artifacts/perf/`。 |
| `window.__civPerf.dragCamera(...)` | 自动拖拽地图。 | 用于 `PERF-MAP-16-PAN`。 |
| `window.__civPerf.zoomCamera(...)` | 自动连续缩放。 | 用于 `PERF-MAP-20-ZOOM`。 |
| `window.__civPerf.runTurns(count)` | 自动执行回合。 | 用于 `PERF-TURN-30`。 |
| `window.__civPerf.saveGame/loadGame` | 存读档压力。 | 用于 `PERF-SAVE-LOAD`。 |

代表性自动化用例先写 5 个：`PERF-MAP-16-PAN`、`PERF-MAP-20-ZOOM`、`PERF-DEBUG-HEAVY`、`PERF-TURN-30`、`PERF-SAVE-LOAD`。这些用例通过后，才继续补全 25 中的完整矩阵。

### 性能 Trace 最小字段

`PerfTrace` 至少包含：

| 字段 | 说明 |
| --- | --- |
| `caseId` | 用例 ID，例如 `PERF-MAP-16-PAN`。 |
| `buildVersion` / `rulesVersion` | 用于比较不同版本。 |
| `browser` / `viewport` / `dpr` | 用于解释浏览器和设备差异。 |
| `mapSeed` | 固定地图种子。 |
| `frame.avgFps` / `frame.p95Ms` / `frame.maxMs` | 判断卡顿。 |
| `render.activeChunk` / `render.activeTile` / `render.spriteCount` | 判断渲染对象压力。 |
| `turn.totalMs` / `turn.aiMs` / `turn.autosaveMs` | 判断结束回合压力。 |
| `storage.saveSizeBytes` / `storage.writeMs` / `storage.readMs` | 判断存读档压力。 |
| `warnings` | 记录超预算或采样缺失。 |

## 十一、调试面板

Debug Panel 是第一版必做工具，建议用 React DOM 实现，不进入 PixiJS 画布。

| 页签 | 内容 | 第一版要求 |
| --- | --- | --- |
| Overview | 回合、阶段、当前玩家、地图 seed、胜利进度、资源摘要。 | 必须。 |
| Performance | FPS、avg/p50/p95/max frame time、input latency、long task count、Command trace、EndTurn trace。 | 必须。 |
| Selection | 当前 tile/unit/city 的完整规则数据和派生值。 | 必须。 |
| EventLog | 玩家操作、AI 意图、资源结算、战斗、科技、胜利事件。 | 必须。 |
| AI Intent | AI 当前策略、目标城市/单位、评分、选择原因、失败原因。 | 必须。 |
| Render | active chunk、active tile、mounted/unmounted per second、Sprite/Container/Graphics/Text 数、overlay 开关、相机坐标、缩放、screenToTile 结果。 | 必须。 |
| Storage | 存档槽、schemaVersion、存档大小、最近读写耗时、last error。 | 建议。 |
| Worker | 请求列表、payload size、耗时、超时、错误、取消状态、discarded stale response count。 | WorkerLikeClient 启用后必须。 |
| Commands | 最近 Command、ValidationResult、状态 diff 摘要。 | 必须。 |
| Tools | 导出 Debug、导入 Debug、跳回合、触发胜利、重置地图。 | 建议 gated 到开发模式。 |

## 十三、Debug Export

Debug Export 用于复现 bug、分析试玩和回归测试。建议导出单个 JSON 文件。

| 字段 | 内容 | 是否必需 |
| --- | --- | --- |
| `metadata` | `buildVersion`、导出时间、浏览器、平台、地图 seed。 | 必需 |
| `gameState` | 当前纯数据 GameState。 | 必需 |
| `commandLog` | 成功执行的 Command 列表。 | 必需 |
| `rejectedCommands` | 最近失败 Command 和错误码。 | 建议 |
| `eventLog` | 最近关键事件，至少最近 200 条。 | 必需 |
| `aiIntentLog` | AI 决策、评分、原因、失败项。 | 必需 |
| `perfSamples` | FPS、frame time、Command trace、EndTurn trace。 | 必需 |
| `storageInfo` | 存档槽、大小、schemaVersion、读写耗时。 | 建议 |
| `uiState` | 选中对象、相机、overlay 开关。 | 建议 |
| `errorLog` | 未捕获错误、Worker 错误、WebGL context lost。 | 必需 |

导出文件不能包含 PixiJS Texture、Sprite、DOM 节点、函数、循环引用或用户隐私信息。

## 十四、AI 意图日志

AI 不是只输出 Command，还要输出“为什么这么做”。第一版 AI 简单也必须可解释。

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `turn` | 决策回合。 | `12` |
| `playerId` | AI 玩家。 | `ai_1` |
| `strategy` | 当前大方向。 | `explore` / `expand` / `defend` / `attack` / `science` |
| `candidateActions` | 候选动作和评分。 | 建城 82 分，造弓手 61 分 |
| `chosenCommands` | 最终输出的 Command。 | `MOVE_UNIT`, `SET_CITY_PRODUCTION` |
| `reason` | 选择理由。 | “附近有高生产地块，且城市数低于玩家。” |
| `rejectedByValidator` | 被主线程拒绝的命令。 | `TILE_BLOCKED` |
| `visibleThreats` | AI 看到的敌军/城市压力。 | 敌方战士距离首都 4 格 |
| `resourcePressure` | 资源短缺或优势。 | 金币为负，优先市场 |
| `victoryPressure` | 胜利压力判断。 | 玩家科技领先 2 项 |
| `durationMs` | AI 决策耗时。 | `128` |

AI 意图日志展示要求：

| 要求 | 说明 |
| --- | --- |
| 只展示 AI 可见信息 | 避免调试面板误导规则设计。开发模式可以另开“全知视角”。 |
| 失败也记录 | AI 输出非法 Command 时必须记录被拒绝原因。 |
| 可过滤 | 按策略、单位、城市、回合过滤。 |
| 可导出 | Debug Export 必须包含最近 AI 意图。 |

## 十五、错误与异常监控

| 错误类型 | 捕获方式 | 处理要求 |
| --- | --- | --- |
| Validator 失败 | CommandBus 返回 `ValidationResult`。 | 展示原因，记录 `command_rejected`。 |
| Simulation 异常 | try/catch + 错误边界。 | 停止当前 Command，保留 Debug Export 能力。 |
| React 渲染错误 | Error Boundary。 | 显示错误面板，允许导出调试信息。 |
| Worker 错误 | `onerror` / timeout / rejected response。 | 回退主线程或跳过 AI，记录错误。 |
| IndexedDB 失败 | Promise catch。 | 提示存档失败，不破坏当前 GameState。 |
| WebGL context lost | canvas 事件监听。 | 暂停渲染，尝试恢复资源，记录错误。 |
| Asset 加载失败 | AssetManager 统一捕获。 | 使用占位图或禁用对应音效。 |
| 性能超预算 | 采样器触发阈值。 | 写入日志，不直接中断游戏。 |

## 十六、验收标准

| 类别 | 第一版必须达到 |
| --- | --- |
| Simulation | 地图、移动、城市、资源、科技、战斗、胜利核心规则都有单测。 |
| Validator | 非法移动、科技前置、城市上限、单位归属、不可通行都有错误码测试。 |
| 回放 | 固定 seed + CommandLog 可重放到一致状态。 |
| 存档 | 第 10 回合保存、刷新、读档、继续到第 30 回合可通过。 |
| Playwright | 首屏、移动、城市生产、科技、结束回合、调试面板、存档读档冒烟通过。 |
| 性能 | 默认 16x16 地图拖拽缩放平均 60 FPS，低端不低于 30 FPS。 |
| 结束回合 | 默认规模下结束回合低于 1000ms，AI 决策低于 800ms。 |
| 调试面板 | FPS、回合、选中对象、资源结算、AI 意图、胜利进度可见。 |
| Debug Export | 能导出 metadata、GameState、CommandLog、EventLog、AI Intent、PerfSamples。 |
| 试玩数据 | 能记录首回合完成、首次移动、首次科技、首次生产、非法操作、胜利结果。 |

## 十七、风险清单

| 风险 | 影响 | 预防措施 |
| --- | --- | --- |
| 规则测试依赖 PixiJS/DOM | 测试慢且难复现，规则和表现耦合。 | Simulation 测试禁止 import 渲染/UI。 |
| GameState 含不可序列化对象 | 存档、回放、Worker 都会出问题。 | schema 校验，Debug Export 检查纯数据。 |
| 回放结果不一致 | bug 难复现，AI/战斗无法验证。 | 统一 RNG，记录 command 顺序和 rngState。 |
| Playwright 只测 UI 不测规则 | 表面能点，公式错误没被发现。 | 规则靠单测，Playwright 只做端到端冒烟。 |
| 性能指标只有平均值 | 卡顿被平均值掩盖。 | 必须记录 p95/max frame time。 |
| AI 决策不可解释 | 不知道 AI 是笨、作弊还是规则错。 | AI Intent Log 必做，候选评分可导出。 |
| 调试工具污染正式玩法 | 玩家误开作弊工具或状态被改坏。 | Debug Tools 只在开发模式或显式开关下启用。 |
| 埋点过多影响性能 | 测试版本变卡，数据噪音大。 | 采样、批量写入、只记录关键事件。 |
| 存档迁移缺失 | 早期试玩存档无法打开。 | 从第一版就带 `schemaVersion` 和迁移测试。 |
| Worker 通信过重 | AI 本来想降卡顿，结果序列化更慢。 | Worker payload 用裁剪快照，记录 payload size。 |
| WebGL context lost 未处理 | 浏览器恢复后画面黑屏。 | 第二版前可简化处理，但第一版要记录并提示刷新。 |
| 手工试玩反馈不可复现 | 只听描述无法定位问题。 | 试玩要求同时导出 Debug JSON。 |

## 十八、推荐实现顺序

| 顺序 | 内容 | 退出标准 |
| --- | --- | --- |
| 1 | 建立 Simulation 单测框架和 fixture。 | 可在无浏览器环境测试城市、资源、移动。 |
| 2 | 加入 CommandLog 和重放测试。 | 固定 seed + 命令序列可得到一致状态。 |
| 3 | 实现 Debug Panel 基础页签。 | Overview、Performance、EventLog、Selection 可用。 |
| 4 | 实现 Playwright 冒烟测试。 | 首屏、移动、科技、生产、结束回合通过。 |
| 5 | 实现 Debug Export。 | 导出 JSON 可用于本地重放测试。 |
| 6 | 加入性能采样。 | FPS、p95、EndTurn trace、AI trace 可见。 |
| 7 | 加入试玩埋点。 | 能导出 session 行为数据。 |
| 8 | 完善 AI Intent Log。 | AI 决策原因、评分、失败命令可见。 |

第一版只要把这些工具做扎实，后续扩玩法、换地图形态、迁移 Worker 或优化 WebGL 时，问题都会更容易定位。
