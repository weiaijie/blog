# 25 压力测试矩阵与容量规划

## 一、结论

现有文档已经覆盖了地图压力、回合计算压力和渲染性能指标，但压力测试表还不够集中。真正容易漏的不是单项性能，而是**组合压力**：

- 玩家连续拖拽缩放时，AI 正在结算。
- Debug Overlay 开启时，地图对象和文本暴涨。
- 长日志局面下自动存档和 Debug Export 变大。
- 低端设备、高 DPR、Safari/Firefox 行为差异导致同一场景表现不同。
- Worker 超时、IndexedDB 失败、WebGL context lost 等异常和压力同时发生。

因此第一版需要一张统一压力矩阵。所有指标仍然是**预算和验收目标**，不是已实测结论。必须等 Web 原型可运行后用 Debug Panel、Performance API、Playwright 和人工拖拽测试确认。

本文件是压力场景矩阵，不替代可执行测试规格。每个用例进入实现前还需要绑定 `fixture/seed`、脚本步骤、采样窗口、硬阈值、trace 产物路径和负责人。

## 十二、性能基线协议

压力矩阵只有在测试环境固定后才有比较价值。每次性能实测必须记录下面字段，否则数据不能进入基线。

| 字段 | 第一版固定值或记录方式 |
| --- | --- |
| `buildVersion` | 从应用构建版本读取，Debug Export 必须带出。 |
| `rulesVersion` | 从规则配置版本读取，调参后必须变化。 |
| `browser` | 至少记录 Chrome/Edge 版本；Safari/Firefox 冒烟另记。 |
| `viewport` | 桌面默认 `1440x900`；小屏压力用 `1024x768`。 |
| `deviceScaleFactor` | 默认 `1`；DPR 压力分别测 `1`、`1.5`、`2`。 |
| `mapSeed` | 默认 `perf-default-16`；压力图 `perf-stress-20`；坏数据图另列。 |
| `warmup` | 进入场景后先等待 3 秒，不记录；避免资源加载和首帧污染采样。 |
| `sampleWindow` | 地图拖拽/缩放每次采样 10 秒；长时间运行采样 30 分钟。 |
| `tracePath` | `artifacts/perf/<buildVersion>/<caseId>.json`。 |
| `blockingRule` | MVP 阻断项：平均 FPS < 30、p95 frame time > 33ms、结束回合 > 1000ms、AI > 800ms、存档写入 > 500ms。 |

第一版先跑 Chromium 自动化，Chrome/Edge 人工复核。Safari/Firefox 作为试玩前冒烟，不作为早期开发阻断项，但异常必须记录。

## 十三、浏览器实测调用规范

### 1. 页面必须暴露的测试接口

为了让 Playwright 能稳定驱动性能场景，开发模式下页面需要暴露 `window.__civPerf`。这些接口只能在开发/测试构建启用。

```ts
type CivPerfApi = {
  loadScenario: (scenarioId: string) => Promise<void>;
  startTrace: (caseId: string, options?: { sampleWindowMs?: number }) => void;
  stopTrace: () => Promise<PerfTrace>;
  dragCamera: (options: { direction: "east" | "west" | "north" | "south"; durationMs: number }) => Promise<void>;
  zoomCamera: (options: { cycles: number; center: { x: number; y: number } }) => Promise<void>;
  runTurns: (count: number) => Promise<void>;
  openDebugOverlay: (preset: "off" | "light" | "heavy") => Promise<void>;
  saveGame: (slotId: string) => Promise<void>;
  loadGame: (slotId: string) => Promise<void>;
  exportDebug: () => Promise<DebugExport>;
};

declare global {
  interface Window {
    __civPerf?: CivPerfApi;
  }
}
```

### 2. Performance API 采样器

渲染层每帧调用 `recordFrame`。回合、AI、寻路、存档使用 `performance.mark()` / `performance.measure()` 包住阶段。

```ts
type FrameSample = {
  t: number;
  dt: number;
};

type PerfTrace = {
  caseId: string;
  buildVersion: string;
  browser: string;
  viewport: { width: number; height: number; dpr: number };
  mapSeed: string;
  durationMs: number;
  frame: {
    avgFps: number;
    p50Ms: number;
    p95Ms: number;
    maxMs: number;
    longTaskCount: number;
  };
  render: {
    activeChunk: number;
    activeTile: number;
    spriteCount: number;
    containerCount: number;
    graphicsCount: number;
    textCount: number;
  };
  turn?: {
    totalMs: number;
    aiMs: number;
    pathfindingMs: number;
    visionMs: number;
    autosaveMs: number;
  };
  storage?: {
    saveSizeBytes: number;
    writeMs: number;
    readMs?: number;
  };
  warnings: string[];
};
```

示例调用：

```ts
performance.mark("turn:start");

performance.mark("turn:ai:start");
await aiClient.planTurn(request);
performance.mark("turn:ai:end");
performance.measure("turn:ai", "turn:ai:start", "turn:ai:end");

performance.mark("turn:autosave:start");
await storage.save("autosave_latest", saveGame);
performance.mark("turn:autosave:end");
performance.measure("turn:autosave", "turn:autosave:start", "turn:autosave:end");

performance.mark("turn:end");
performance.measure("turn:total", "turn:start", "turn:end");
```

### 3. Long Task 与内存采样

浏览器支持时启用 `PerformanceObserver`。不支持时字段留空，但不能阻塞测试。

```ts
const longTasks: PerformanceEntry[] = [];

const observer = new PerformanceObserver((list) => {
  longTasks.push(...list.getEntries());
});

observer.observe({ entryTypes: ["longtask"] });
```

`performance.memory` 只有部分 Chromium 环境可用，记录时必须标注 `memoryAvailable: true/false`。
