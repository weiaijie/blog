# 20 全量文档证据核查报告

## 一、核查结论

当前目录已有 28 份 Markdown 文档。本报告仍以证据核查为目标，但后续新增的 21-25 文档已经把性能调度、地图规模、地图引擎先行、整体缺口复查和压力矩阵纳入范围；后续若继续新增 26-28，应同步更新本报告。

这次核查把现有文档中的内容分成四类：

| 类型 | 含义 | 处理方式 |
| --- | --- | --- |
| 官方资料可证实 | Web API、引擎能力、部署工具、游戏类型定义等可由官方或明确来源证明。 | 保留，并在本报告和资料来源中列出依据。 |
| 项目设计决策 | 30 回合、12x12 到 20x20、四种资源、两个胜利条件、PixiJS + React 分层等。 | 保留，但明确这是当前项目选择，不是行业事实。 |
| 性能预算/验收目标 | 60 FPS、30 FPS、p95 33ms、AI 800ms、存档 500ms 等。 | 全部标为目标或预算，不能当成已验证事实。 |
| 待本地实践验证 | CPU 命中是否足够快、PixiJS Sprite tilemap 是否支撑 20x20、DPR 封顶是否合适等。 | 放入 Spike/测试清单，必须由原型采样验证。 |

最重要的修正：**性能相关数字目前没有本地原型数据支撑，只能作为预算目标和验收阈值，不是已达成结论。**

## 八、结论

当前 28 份文档已经完成主题覆盖，但不能把所有数字和建议都视为事实。经过本轮核查后：

- 外部技术事实已有官方资料支撑。
- 项目设计选择已明确属于决策，不伪装成行业事实。
- 性能数字已明确为预算/目标，不再当成已验证结果。
- 需要本地实践的内容已经列成 Spike 清单。

下一步如果要继续提高可信度，就不是继续写调研，而是按 [17_浏览器兼容与技术验证清单.md](./17_浏览器兼容与技术验证清单.md) 和 [18_MVP开发路线与任务拆解.md](./18_MVP开发路线与任务拆解.md) 做最小原型实测。
