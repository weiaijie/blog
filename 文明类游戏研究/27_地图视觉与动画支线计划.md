# 27 地图视觉与动画支线计划

本文档定义地图视觉与动画支线的目标、边界、验收和测试命令。该支线是并行表现层任务，不阻塞 Phase 3 规则与玩法主线；主线继续推进可玩闭环，视觉支线只在渲染、动画、视觉反馈和相关文档内迭代。

## 一、支线目标

地图视觉与动画支线只解决“玩家看得清、操作反馈明确、地图表现稳定”的问题，不改变规则结果。

| 目标 | 成功标准 |
| --- | --- |
| 地形可读性 | 不同地形、资源和可通行感能快速区分，缩放和拖拽时不糊成一片。 |
| 迷雾可读性 | visible、explored、unknown 三类状态层次清楚，不泄露规则层不该暴露的信息。 |
| 选中和 hover 反馈 | 地块、单位、可执行目标有明确但克制的视觉反馈，且不写入 `GameState`。 |
| 单位表现 | 单位图标、阵营归属、生命/状态提示能被玩家理解，不抢占规则开发节奏。 |
| 移动和操作动画 | 动画只表现已确认的规则结果，不提前预测或修改规则状态。 |
| 性能稳定 | 地图拖拽、缩放、迷雾和反馈层继续通过现有性能门禁。 |

## 四、不影响主线的规则

1. 使用独立分支或独立提交推进视觉支线；默认分支名为 `codex/map-visual-animation-track`。
2. 每次只做一个视觉小闭环，例如地形视觉增强、迷雾可读性增强、选中态/hover 态、单位图标、移动动画。
3. 改动前先确认不动规则层：

```powershell
git diff -- src/game
```

如果 `src/game` 有变化，必须先判断是否来自本支线；非视觉支线改动不得混入本支线提交。

4. 视觉反馈不得写入 `GameState`、`CommandLog`、SavedGame 或 replay/hash。hover、选中、推荐方向、动画播放状态属于 UI/render 状态。
5. 动画只能响应规则层已经确认的结果。禁止为了动画流畅而提前更改单位坐标、视野、资源或战斗结果。
6. 迷雾表现只能读取现有 exploration 数据。可见、已探索、未知的展示必须和规则层状态一致，不得在 UI 中猜测隐藏信息。
7. 性能优化不能牺牲规则一致性。允许临时降低表现成本，例如拖拽期间降低或隐藏重型视觉层，但不得改规则状态。

## 五、每阶段验收

| 阶段 | 范围 | 验收 |
| --- | --- | --- |
| Visual Phase 0 | 地形和迷雾可读性优化 | 默认地图首屏能区分主要地形与三类迷雾状态；`smoke:playable` 和地图性能通过。 |
| Visual Phase 1 | 选中态、hover 态、可执行目标反馈 | 地块/单位/合法目标反馈清楚；无规则层 diff；smoke 覆盖关键状态。 |
| Visual Phase 2 | 单位图标与状态提示 | 单位阵营、类型、基础状态可读；不改变单位规则数据。 |
| Visual Phase 3 | 移动和操作动画 | 动画只表现已执行命令；操作期间不阻塞输入或污染 replay/hash。 |
| Visual Phase 4 | 视觉资产整理 | 视觉参数、纹理生成或占位资产有明确目录；加载失败有可接受 fallback。 |

每个阶段完成后，更新本文档的“当前优先任务”和必要的验收记录。进入下一阶段前至少跑完相关 smoke；改 Pixi 地图、迷雾或动画时必须跑地图性能用例。

## 七、当前优先任务

Visual Phase 0 第一轮已经完成地形和迷雾可读性优化，但后续视觉设计不再直接在主线地图里边改边试。先使用独立视觉模块工坊 `http://127.0.0.1:5173/?view=visual-lab` 设计和调试地形块、过渡、单位、可建设对象与动画状态，确认后再迁入主线地图。工坊使用 Three.js 做 3D 灰盒预览和组合验收；最终精细模型不在代码里硬搓，必须走 Blender/glTF 资产管线。主线 Pixi 地图不直接依赖未确认的 3D 试验。

1. Visual Phase 0.5：视觉模块工坊完善。
2. 先在 `src/render/visuals/tileModuleCatalog.ts` 和 `src/ui/visualFeedback/VisualModuleWorkbench.tsx` 中单独设计地形块、地形过渡、单位、可建设对象和动画状态。
3. 建立 `src/render/assets/` 资产管线说明：Blender 源文件、glTF/GLB 导出、terrain/transition/unit/buildable 命名和 LOD 约定。
4. 主线地图只消费已经确认的主题、资产和渲染参数；不要把未确认的视觉试验直接塞进 `mountPixiStage.ts`。
5. 每次模型评审先看组合地图：水陆岸线、森林边缘、丘陵坡脚、道路、单位和建筑必须在同一镜头下检查，不只看单块贴色。
6. 提交前确认 `git diff -- src/game` 为空。
7. 跑 `npm run typecheck`、`npm run test`、`npm run lint`、`npm run smoke:playable`；若最终迁入 Pixi 地图或迷雾，再跑 `npm run perf:map:all` 和 `npm run perf:map:fog`。
