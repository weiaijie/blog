# 26 开工总体项目规划

本文档把前面 00-25 的研究、架构、规则、测试和性能要求收敛成开工执行计划。目标是让第一版 Web 原型尽快跑起来，同时不牺牲后续调试、存档、回放和性能验证能力。

## 一、项目目标

第一版不是做完整文明类游戏，而是做一个能被试玩、可复现、可调参的 30 回合 Web 原型。

| 目标 | 成功标准 |
| --- | --- |
| 核心循环成立 | 玩家能完成 30 回合，经历探索、建城、生产、研究、AI 压力和胜利结算。 |
| 地图体验成立 | 默认 16x16 方格地图可拖拽、缩放、选中、显示单位/资源/迷雾；20x20 压力图可测。 |
| 规则可验证 | 移动、建城、资源、生产、科技、战斗、胜利都有 Simulation 单测。 |
| 状态可复现 | `GameState` 纯数据化，`RuleCommand` 进入 `CommandLog`，Debug Export 可复盘问题。 |
| 性能可观测 | 有 FPS、p95 frame time、TurnTrace、Render stats、Storage trace、WorkerLike trace。 |
| 可发链接试玩 | Vite build 可静态部署，玩家能打开链接试玩并导出 Debug JSON。 |

## 二、开工原则

| 原则 | 执行要求 |
| --- | --- |
| 先闭环，后加内容 | 先让 1 城、2 单位、1 个 AI、少量科技跑通，再加单位、建筑和 UI。 |
| 规则先于表现 | `game/` 规则层不依赖 React、PixiJS、DOM。 |
| 地图引擎先行 | 第一版就有 `CoordinateSystem`、`ViewportManager`、轻量 `ChunkManager`、`TilePool` 和 active area 统计。 |
| 所有规则变化走 `RuleCommand` | UI 选中、hover、相机移动只进 `UIState`，不污染 replay。 |
| 性能测试前移 | M0.5 开始有 Performance sampler；M1 开始能记录地图 pan/zoom trace。 |
| 调试工具不是后置功能 | Debug Panel、EventLog、TurnTrace、Debug Export 是 MVP 的组成部分。 |
| 数值先粗后细 | 初始数值只要能形成选择，平衡靠固定 seed、日志和试玩复盘迭代。 |

## 四、阶段计划

### Phase 0：开工准备

| 工作 | 产物 | 验收 |
| --- | --- | --- |
| 初始化 Web 项目 | Vite + TypeScript + React + PixiJS | `npm run dev` 能打开空页面。 |
| 建立目录边界 | `game/render/ui/storage/workers/perf` | 规则层无 React/PixiJS import。 |
| 接入基础脚本 | `typecheck`、`test`、`dev`、`build` | 空项目 CI 本地可跑。 |
| 建立配置表 | terrain、unit、building、tech 初始配置 | 配置 ID 稳定，可被规则层读取。 |

退出标准：能打开页面，看到空 WebGL canvas 和基础 DOM UI。

### Phase 1：地图引擎骨架

| 工作 | 产物 | 验收 |
| --- | --- | --- |
| 坐标系统 | `CoordinateSystem` | square tile/world/screen 转换单测通过。 |
| 相机控制 | `CameraController` | 拖拽、滚轮缩放、clamp 生效。 |
| 视口与 chunk | `ViewportManager`、轻量 `ChunkManager` | active area、active chunk 可在 Debug 显示。 |
| TilePool | tile/resource/fog sprite 池 | 读档重建或切图时对象数不无界增长。 |
| 性能采样 | `PerformanceSampler` | `PERF-MAP-16-PAN` 能输出 trace。 |

退出标准：16x16 和 20x20 固定地图可显示、拖拽、缩放、点击命中，并输出 p95 frame time、Sprite 数、active tile/chunk。

### Phase 2：规则内核

| 工作 | 产物 | 验收 |
| --- | --- | --- |
| GameState schema | 以 `10_数据结构与存档方案.md` 为准 | `createInitialGameState(seed)` 可重复生成。 |
| RuleCommand | 移动、建城、生产、研究、攻击、结束回合 | 所有规则变化写入 CommandLog。 |
| Validator | 错误码和中文原因 | 非法移动、城市上限、科技前置有测试。 |
| Simulation | 资源、生产、科技、维护、胜利 | 关键公式单测通过。 |
| TurnStateMachine | `PLAYER_ACTION -> ... -> NEXT_TURN` | EndTurn trace 阶段顺序固定。 |

退出标准：无 UI 也能用固定命令跑 10 回合，并得到稳定 GameState hash。

### Phase 3：最小可玩闭环

| 工作 | 产物 | 验收 |
| --- | --- | --- |
| 城市系统 | 首都、新城、人口、生产队列 | 城市可生产单位/建筑。 |
| 单位系统 | 侦察兵、战士、建造者、弓手 | 移动、探索、建城、攻击可用。 |
| 科技系统 | 8-12 个科技、天文台计划 | 科技解锁和科技胜利路径可用。 |
| 战争迷雾 | explored/visible 状态 | 单位移动后迷雾更新并记录耗时。 |
| 胜利结算 | 征服、科技、30 回合分数 | 三种胜利可用 debug 方法触发。 |

退出标准：玩家能从第 1 回合玩到第 30 回合，哪怕 UI 还很粗。

### Phase 4：AI、轻外交、存档

| 工作 | 产物 | 验收 |
| --- | --- | --- |
| AIReadableState | AI 裁剪状态 | 不传 UI/render 状态给 AI。 |
| AI 评分 | 探索、扩张、经济、科研、防御、进攻 | 每回合有主意图、评分、原因。 |
| WorkerLikeClient | requestId、timeout、discard stale response | 主线程 fallback 与未来 Worker 同协议。 |
| 轻外交 | unknown/peace/tense/war、关系值、原因 | 不做外交交易；宣战可解释。 |
| IndexedDB 存档 | autosave、manual_001 | 刷新后能恢复同一局。 |
| Debug Export | GameState、CommandLog、EventLog、AI、perf | 导出 JSON 可用于复现。 |

退出标准：AI 能制造压力；读档不会被旧 AI 响应污染；Debug Export 能解释问题。

### Phase 5：UI、教学、复盘

| 工作 | 产物 | 验收 |
| --- | --- | --- |
| 顶部状态栏 | 回合、资源、科技、胜利压力 | 玩家随时知道当前状态。 |
| 城市面板 | 人口、产出、生产队列、建筑 | 玩家能理解城市为什么产出。 |
| 科技面板 | 成本、前置、预计完成回合 | 玩家能选择科技路线。 |
| 单位/地块 Tooltip | 产出、移动、战斗预览 | 非法操作有明确解释。 |
| 前 5 分钟教学 | 移动、生产、科技、结束回合 | 新玩家能完成前 5 回合。 |
| 复盘面板 | 胜负原因、分数来源、关键回合 | 玩家能说出自己为什么赢/输。 |

退出标准：新玩家不看文档也能玩过前 5 回合。

### Phase 6：性能、测试、部署

| 工作 | 产物 | 验收 |
| --- | --- | --- |
| Playwright 冒烟 | 首屏、移动、生产、科技、结束回合、存读档 | 本地自动跑通。 |
| 代表性能用例 | `PERF-MAP-16-PAN` 等 5 个 trace | 阻断阈值通过或形成优化任务。 |
| 压力图 | `perf-stress-20` | 20x20 可运行并输出 trace。 |
| 静态部署 | Vite build + 静态站点 | 可发链接试玩。 |
| 试玩包 | 构建版本、玩法说明、Debug Export 指引 | 试玩反馈可复现。 |

退出标准：可公开给小范围玩家试玩，并能收回可分析的问题数据。

## 七、质量门禁

| 阶段 | 不满足时不能继续 |
| --- | --- |
| M0 | `npm run build`、`npm run test`、`npm run typecheck` 至少有基本脚本。 |
| M0.5 | 16x16/20x20 地图 pan/zoom 有 trace，p95 可读。 |
| M2 | 规则层单测不 import React/PixiJS/DOM。 |
| M3 | 同 seed + 同 RuleCommand 序列得到相同 GameState hash。 |
| M5 | AI 每回合有意图、评分、原因；非法命令被 Validator 拒绝并记录。 |
| M6 | 读档后旧 WorkerLike 响应不会污染当前局。 |
| M8 | 5 个代表性能用例有 JSON trace 和人工摘要。 |

## 八、风险优先级

| 风险 | 优先处理方式 |
| --- | --- |
| 规则和渲染耦合 | 目录边界 + import 检查 + 规则单测。 |
| 地图性能不可控 | M0.5 提前做 pan/zoom trace，不等玩法完整。 |
| AI 不可解释 | AI 第一版就输出评分和原因，不先做黑箱行为。 |
| 存档污染 | GameState 纯数据校验，读档时重建 render/UI。 |
| 玩法不形成压力 | 固定 seed 试玩，记录首次接敌、第二城、首次战斗、胜利压力回合。 |
| 范围膨胀 | 第一版不做外交交易、多人、海战、宗教、完整移动端。 |

## 九、当前不建议做

| 不建议事项 | 原因 |
| --- | --- |
| 先画复杂美术 | 会拖慢规则和性能验证。 |
| 先做完整科技树 | 数值和平衡工作量会失控。 |
| 先做完整外交交易 | Command、UI、AI、测试都会放大范围。 |
| 先上 WebGPU | 兼容和调试成本高，WebGL/PixiJS 足够验证 MVP。 |
| 先做 32x32/64x64 默认地图 | 玩法和性能都还没有基线。 |
| 把调试工具后置 | 后续 AI、存档、数值问题会难以复现。 |

| 带迷雾性能用例 | 已新增 `window.__civPerf.setExploration` 和 `npm run perf:map:fog`，顺序生成 16x16/32x32/64x64 fog pan artifact。subagent 复核确认：pan trace 中不应优化 `renderFog()` 绘制/上传路径，主要成本来自 fog sprite 每帧 GPU 采样/alpha blend；拖拽期间临时隐藏 fog sprite 不影响 `currentExploration`、规则一致性或 smoke 计数。 | 最新保留改动：32x32/64x64 使用 nearest fog texture 采样，小图保留 linear；真实 pointer drag 和 perf API `dragCamera` 期间临时隐藏 fog sprite，120ms 空闲后恢复。`npm run verify:phase2` 最新顺序复测：16x16 fog pan PASS p95 14.4ms，32x32 fog pan PASS p95 14.4ms，64x64 fog pan PASS p95 12.8ms；无 over20/over33。 |
| Phase 2 收尾质量门 | 已新增 `npm run verify:phase2`，把 typecheck、test、lint、普通地图性能、带迷雾性能、可玩 smoke、30 回合 smoke 串成一键回归。 | 最新执行通过，用时约 99 秒；`npm run test` 为 12 个测试文件、35 个用例；`smoke:playable` 和 `smoke:30turn` 均在 production preview 下通过。 |

阶段结论：Phase 2 可见 MVP 闭环已达到“可人工试玩”标准。当前版本可以连续操作 30 回合，规则变更可 replay/hash/save，地图无迷雾性能基线稳定，并已有最小探索/迷雾状态与地图表现。带迷雾 pan 性能已通过 production-preview 基线：拖拽期间使用低成本 fog 表现，停止拖拽后恢复完整迷雾。它仍不是完整文明类游戏，暂不包含复杂 AI、外交、贸易、建筑树和正式数值平衡。

下一步优先队列：

1. Phase 2 收尾质量门已成型，后续每轮重要改动优先跑 `npm run verify:phase2` 或按影响面拆跑其中子项。
2. 探索体验提示和 UI 中文化已补齐，下一步转入“正式阶段拆分”：明确 Phase 3 的最小可玩范围、验收和不做清单。
3. 继续维护拖拽低成本 fog 约束：只允许临时改变 `fogSprite.visible`，不得改 `currentExploration` 或规则状态。
