# 14 AI 与外交可解释性

本文档定义第一版 30 回合 Web 原型中的 AI 和轻外交方案。目标不是做复杂外交模拟，而是让 AI 能完成探索、扩张、研究、生产、防御、进攻这些基础行为，并且让玩家和开发者都能看懂“AI 为什么这么做”。

第一版核心原则：

| 原则 | 决策 |
| --- | --- |
| AI 只输出意图和 Command | AI 不直接改 `GameState`，所有行动仍走 `CommandBus -> Validator -> Simulation`。 |
| 解释优先 | 每个关键 AI 决策必须写入 `aiIntentLog`，包含评分、目标、原因和失败项。 |
| 轻外交 | 第一版只做关系值、状态、宣战、敌意变化，不做交易、同盟、议和、复杂谈判。 |
| 不作弊或少作弊 | 玩家可见 UI 只展示 AI 合法可见信息；开发模式可打开全知调试。 |
| 可复现 | AI 决策只依赖裁剪后的状态、固定 RNG 和明确权重，不依赖真实时间。 |
| 可降级 | Worker 超时或失败时，AI 使用保守行动，例如防守、补生产、结束回合。 |

## 一、第一版范围

| 模块 | 第一版做 | 第一版不做 |
| --- | --- | --- |
| AI 玩家 | 1 个 AI 对手。 | 多 AI、多阵营联盟。 |
| AI 意图 | 探索、扩张、经济、科研、防御、进攻。 | 长期人格、复杂心理模型。 |
| AI 行动 | 选科技、选生产、移动、建城、防守、攻击、宣战。 | 复杂交易、外交勒索、协同战术。 |
| 外交状态 | 未接触、和平、紧张、战争。 | 结盟、附庸、开放边境、停战谈判。 |
| 关系变化 | 接触、靠近边境、扩张竞争、军事威胁、攻击、科技压力。 | 深层承诺、声誉系统、全球外交记忆。 |
| 可解释性 | AI 意图面板、外交原因、回合日志、Debug Export。 | 自然语言对话式外交。 |

## 二、AI 行为模型

第一版采用“分层评分 + Command 输出”模型。

```text

AIReadableState
  -> 局势分析 SituationAnalysis
  -> 战略意图评分 IntentScore[]
  -> 选择主意图 + 次意图
  -> 生成候选行动 CandidateAction[]
  -> 行动评分和排序
  -> 输出 Command[]
  -> 主线程 Validator
  -> Simulation
  -> aiIntentLog / EventLog
```

| 层级 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| 状态裁剪 | `GameState` | `AIReadableState` | 只给 AI 必要规则数据和它已探索/可见的信息。 |
| 局势分析 | `AIReadableState` | `SituationAnalysis` | 计算城市数、单位数、威胁、资源压力、科技差距、胜利压力。 |
| 意图评分 | `SituationAnalysis` | `IntentScore[]` | 给探索、扩张、科研、防守、进攻等方向打分。 |
| 行动生成 | 主意图 + 当前状态 | `CandidateAction[]` | 生成研究、生产、移动、建城、攻击、宣战等候选行动。 |
| 行动选择 | 候选行动 | `Command[]` | 选择分数最高且预算内的行动。 |
| 解释记录 | 全部中间结果 | `AIIntentLogEntry` | 给 UI、调试面板、Debug Export 使用。 |

## 三、AIReadableState

AI Worker 不应拿整棵 `GameState`。第一版建议给 AI 一个裁剪快照。

```ts
type AIReadableState = {
  schemaVersion: number;
  turn: number;
  seed: string;
  rngState: RngState;
  aiPlayerId: PlayerId;
  humanPlayerId: PlayerId;
  map: {
    width: number;
    height: number;
    knownTiles: AIKnownTile[];
  };
  self: AIPlayerSnapshot;
  opponent: AIOpponentSnapshot;
  diplomacy: AIDiplomacySnapshot;
  victory: AIVictorySnapshot;
  recentEvents: AIRelevantEvent[];
};
```

| 字段 | 第一版要求 |
| --- | --- |
| `knownTiles` | 默认只包含 AI 已探索地块；开发模式可传全图并标记 `omniscient = true`。 |
| `self` | 包含 AI 城市、单位、资源、科技、生产队列、当前研究。 |
| `opponent` | 只包含 AI 已接触或已看见的信息，例如已知城市、已知单位、估算科技压力。 |
| `diplomacy` | 包含双方关系值、外交状态、最近关系变化原因、宣战冷却。 |
| `recentEvents` | 最近 20-50 条和 AI 有关的事件，帮助 AI 判断威胁和压力。 |

## 四、意图类型表

| 意图 | 触发条件 | 典型行动 | 玩家可读解释 |
| --- | --- | --- | --- |
| `explore` 探索 | 未探索地块多、未发现玩家、侦察兵存活。 | 移动侦察兵到未知区域、研究侦察。 | “AI 正在探索未知地图，寻找资源和边界。” |
| `expand` 扩张 | 城市数少于上限、发现高价值建城点、经济能承担维护。 | 生产建造者、移动到建城点、建立新城。 | “AI 找到了高产地块，准备建立新城市。” |
| `economy` 经济 | 金币低、维护压力高、城市多但产出弱。 | 研究贸易、建市场、避免继续扩张。 | “AI 金币压力较大，正在补经济。” |
| `science` 科研 | 科技落后、接近科技胜利路线、城市安全。 | 研究书写/数学、建学院、推进天文台计划。 | “AI 正在追求科技路线。” |
| `defend` 防御 | 敌军靠近城市、关系紧张、己方军力低。 | 生产战士/弓手、研究弓术/石工、单位回防。 | “AI 发现边境威胁，正在加强防御。” |
| `attack` 进攻 | 军力占优、敌方城市低防、关系已战争或敌意很高。 | 宣战、集结部队、攻击单位和城市。 | “AI 认为自己拥有军事优势，正在进攻。” |
| `recover` 恢复 | 单位损失大、金币为负、城市受伤。 | 停止进攻、生产防御、修复经济。 | “AI 处于恢复阶段，暂时避免冒险。” |

第一版每回合选择 1 个主意图和最多 1 个次意图。例如主意图 `expand`，次意图 `defend`，就会优先建城，但保留一名战士守家。

## 五、局势分析字段

| 字段 | 计算方式 | 用途 |
| --- | --- | --- |
| `turnPressure` | 当前回合 / 30。 | 后期提高科技胜利和进攻权重。 |
| `cityCountDelta` | AI 城市数 - 玩家已知城市数。 | 判断扩张落后或领先。 |
| `militaryPowerDelta` | AI 可见军力 - 玩家已知军力。 | 判断防御或进攻。 |
| `scienceDelta` | AI 已完成科技数 - 玩家估算科技数。 | 判断科研追赶或冲刺。 |
| `goldPressure` | 金币库存和每回合净收入。 | 判断经济优先级。 |
| `nearbyThreatScore` | 玩家单位距离 AI 城市的威胁评分。 | 触发防御。 |
| `settleOpportunityScore` | 最佳建城点评分。 | 触发扩张。 |
| `capitalRiskScore` | 敌军到首都距离、首都血量、防守单位。 | 触发守都。 |
| `victoryRaceScore` | 玩家/AI 征服、科技、分数胜利压力。 | 触发反制路线。 |

## 六、权重评分示例

意图评分建议使用简单加权，便于调试和调参。

```ts
type IntentScore = {
  intent: AIIntent;
  base: number;
  modifiers: ScoreModifier[];
  total: number;
};

type ScoreModifier = {
  key: string;
  value: number;
  reason: string;
};
```

| 意图 | 基础分 | 加分项 | 减分项 |
| --- | ---: | --- | --- |
| 探索 | 35 | 未探索地块多 +20；未接触玩家 +15；有侦察兵 +10。 | 回合大于 18 -15；首都受威胁 -25。 |
| 扩张 | 30 | 城市数少于 2 +25；最佳建城点大于 70 分 +25；金币净收入非负 +10。 | 已达城市上限 -100；金币为负 -25；敌军靠近首都 -20。 |
| 经济 | 25 | 金币为负 +35；单位维护过高 +20；已解锁市场 +10。 | 已有稳定金币收入 -15；濒临军事失败 -10。 |
| 科研 | 25 | 科技落后 +20；已建学院 +15；接近数学/天文台 +30。 | 首都危险 -25；金币严重为负 -10。 |
| 防御 | 20 | 敌军距离城市 5 格内 +30；军力落后 +25；关系紧张 +10。 | 无敌方接触 -15；军力明显领先 -10。 |
| 进攻 | 15 | 军力领先 +30；敌城低血量 +30；已战争 +25；回合大于 22 +10。 | 关系和平且敌意低 -25；军力落后 -40；金币为负 -10。 |
| 恢复 | 10 | 近期单位损失 +25；城市受伤 +25；金币为负 +20。 | 局势稳定 -15。 |

示例：

| 回合/局势 | 分数结果 | AI 选择 | 可读解释 |
| --- | --- | --- | --- |
| 第 5 回合，未发现玩家，侦察兵存活。 | 探索 80，扩张 45，防御 15。 | `explore` | “AI 还没有发现主要对手，优先探索地图。” |
| 第 12 回合，发现高产建城点，金币净收入 +2。 | 扩张 90，探索 55，经济 20。 | `expand` | “AI 有经济余量，并找到高价值建城点。” |
| 第 18 回合，玩家战士靠近 AI 首都 4 格。 | 防御 85，进攻 35，科研 30。 | `defend` | “玩家军队靠近 AI 首都，AI 转入防御。” |
| 第 24 回合，AI 军力领先且已进入战争。 | 进攻 95，防御 40，科研 30。 | `attack` | “AI 军力占优，认为可以压制玩家城市。” |

## 七、建城点评分

扩张是文明类 AI 的关键。第一版建城点评分要简单但可解释。

| 因素 | 分值 | 说明 |
| --- | ---: | --- |
| 周围 2 格粮食总量 | 每点 +3 | 保障人口成长。 |
| 周围 2 格生产力总量 | 每点 +4 | 保障前期建造效率。 |
| 河流或金币资源 | +8 | 提升经济价值。 |
| 山脉相邻 | +5 | 后续学院科技价值。 |
| 距首都 4-6 格 | +12 | 扩张距离合适。 |
| 距首都超过 6 格 | -12 | 远城维护更高。 |
| 距已有城市小于 4 格 | -100 | 不合法或强烈禁止。 |
| 靠近敌军 | -10 到 -40 | 根据威胁距离递增。 |
| 靠近敌方首都 | -15 | 第一版避免过度前压铺城。 |
| 可连接已探索区域 | +5 | 降低路径和防守成本。 |

```ts
type SettleSiteScore = {
  tileId: TileId;
  total: number;
  factors: ScoreModifier[];
  isLegal: boolean;
  riskLevel: "low" | "medium" | "high";
};
```

## 八、研究选择模型

AI 科技选择根据当前意图决定，不需要复杂科技规划器。

| 当前意图 | 优先科技 | 解释 |
| --- | --- | --- |
| 探索 | 侦察、农业 | 提高视野和基础成长。 |
| 扩张 | 农业、贸易、采矿 | 提高人口、经济和生产。 |
| 经济 | 贸易、农业 | 解锁市场，缓解维护压力。 |
| 科研 | 书写、数学、天文台计划 | 进入科技胜利路线。 |
| 防御 | 采矿、石工、弓术 | 提高生产、防御和远程单位。 |
| 进攻 | 侦察、弓术、战术 | 提供进攻单位和战斗加成。 |

若前置科技未满足，AI 选择通往目标科技的最近前置。若 Validator 拒绝 `CHOOSE_TECH`，日志必须记录被拒原因，并尝试第二候选科技。

## 九、生产选择模型

| 城市状态 | 推荐生产 | 原因 |
| --- | --- | --- |
| 首都第 1 个生产项 | 侦察兵或粮仓 | 探索/成长二选一，根据周围未知地块数量决定。 |
| 城市无防守且附近有威胁 | 战士或弓手 | 保证城市最低防御。 |
| 城市人口成长慢 | 粮仓 | 提高长期产出。 |
| 生产力低 | 工坊 | 支撑后续单位和建筑。 |
| 金币为负或接近为负 | 市场 | 缓解维护。 |
| 科研意图 | 学院 | 提高科技路线速度。 |
| 扩张意图且城市数未满 | 建造者 | 执行建城计划。 |

生产选择必须记录候选项评分：

| 字段 | 示例 |
| --- | --- |
| `cityId` | `city_ai_capital` |
| `candidateItem` | `builder` |
| `score` | `78` |
| `reason` | “AI 城市数低于上限，且发现 82 分建城点。” |

## 十、单位行动模型

| 单位 | 默认行为 | 当前意图修正 |
| --- | --- | --- |
| 侦察兵 | 去最近未知边界，避开敌方军事单位。 | 进攻时可侦查敌城；防御时回撤提供视野。 |
| 战士 | 守城、拦截敌方单位、战争时推进。 | 防御时站在城市 1-2 格内；进攻时向目标城市移动。 |
| 建造者 | 前往最高分合法建城点。 | 高威胁时等待或改走安全路径。 |
| 弓手 | 保持距离攻击，优先守城或压制敌军。 | 防御时站在城市附近；进攻时跟随战士。 |

行动优先级：

| 优先级 | 行动 | 说明 |
| ---: | --- | --- |
| 1 | 城市/首都防御 | 若首都高风险，单位先回防。 |
| 2 | 可击杀目标 | 若能安全击杀敌方单位，优先攻击。 |
| 3 | 建城 | 建造者到达合法高分地块后建城。 |
| 4 | 推进目标 | 进攻或扩张时按路径前进。 |
| 5 | 探索 | 无紧急目标时探索未知区域。 |
| 6 | 原地防守 | 无合法行动或行动风险过高时等待。 |

## 十一、外交状态表

第一版外交只在玩家与 AI 之间存在。

| 状态 | 关系值范围 | 含义 | 可用行动 |
| --- | ---: | --- | --- |
| `unknown` 未接触 | 无 | 双方尚未发现对方城市或单位。 | 无外交 UI，只显示“未接触”。 |
| `peace` 和平 | 0 到 100 | 已接触但未明显敌对。 | 查看关系、查看已知原因。 |
| `tense` 紧张 | -49 到 -1 | 边境、扩张或军力导致关系恶化。 | 查看警告；AI 可准备防御或宣战。 |
| `war` 战争 | -100 到 -50 或宣战后 | 双方可攻击单位和城市。 | 攻击、占城、战争日志。 |

关系值初始化：

| 事件 | 初始/变化 |
| --- | ---: |
| 首次接触 | 关系值设为 20。 |
| 接触时双方军队相距很近 | 额外 -10。 |
| 接触时发现玩家城市靠近 AI 首都 | 额外 -10。 |

## 十二、关系变化表

| 事件 | 关系变化 | 冷却/限制 | 玩家可读解释 |
| --- | ---: | --- | --- |
| 首次接触 | +20 | 只触发一次 | “双方建立接触。” |
| 玩家单位靠近 AI 首都 4 格内 | -8 | 每 3 回合最多一次 | “你的军队靠近了 AI 首都。” |
| 玩家在 AI 首都 6 格内建城 | -15 | 每座城市一次 | “你的新城市被 AI 视为边境压力。” |
| AI 在玩家附近建城 | -8 | 每座城市一次 | “AI 的扩张引发边境紧张。” |
| 玩家军力明显领先 | -8 | 每 5 回合最多一次 | “AI 认为你具有军事威胁。” |
| 玩家科技明显领先 | -5 | 每 5 回合最多一次 | “AI 感受到科技胜利压力。” |
| 玩家攻击 AI 单位/城市 | -50 | 立即进入战争 | “你发动了攻击，战争爆发。” |
| AI 宣战 | 关系设为 -80 | 宣战后进入战争 | “AI 判断战争收益高于和平。” |
| 长时间无冲突 | +3 | 每 5 回合一次，战争中不触发 | “边境暂时稳定。” |
| 玩家和 AI 都处于低军力 | +5 | 每 5 回合一次 | “双方都没有明显进攻能力。” |

第一版关系变化必须进入 `EventLog` 和外交面板，不要只改变数字。

## 十三、宣战条件

AI 宣战必须可解释，避免玩家觉得 AI 突然翻脸。

| 条件 | 第一版规则 |
| --- | --- |
| 外交状态 | 只有 `tense` 或关系值低于 -35 时，AI 才主动考虑宣战。 |
| 军力条件 | AI 军力至少达到玩家已知军力的 1.2 倍，或玩家首都防御明显薄弱。 |
| 目标条件 | AI 必须有明确目标：玩家首都、边境城市、可击杀高价值单位。 |
| 距离条件 | 至少 2 个 AI 军事单位能在 5 回合内抵达目标附近。 |
| 经济条件 | AI 金币不能严重为负，除非首都受到威胁。 |
| 冷却条件 | 首次接触后至少 3 回合内不主动宣战，避免见面秒宣。 |
| 防御宣战 | 玩家先攻击或进入强威胁态时，可绕过部分冷却。 |

宣战评分：

| 因素 | 分值 |
| --- | ---: |
| 关系值低于 -35 | +20 |
| 军力优势大于 1.2x | +25 |
| 玩家边境城市低防 | +20 |
| 玩家科技胜利压力高 | +15 |
| AI 首都受威胁 | +20 |
| 金币为负 | -15 |
| AI 城市少于玩家 | -10 |
| 首次接触未满 3 回合 | -100 |
| 军力低于玩家 | -40 |

当宣战评分大于等于 70，AI 可输出 `DECLARE_WAR`。如果输出后被 Validator 拒绝，AI 本回合转为 `defend`。

## 十四、玩家可读解释

AI 与外交解释分两层：普通玩家解释和开发者调试解释。

| 场景 | 玩家 UI 文案 | Debug 细节 |
| --- | --- | --- |
| AI 转向扩张 | “AI 正在寻找新城市位置。” | 建城点评分、候选地块、路径、维护压力。 |
| AI 转向防御 | “AI 认为边境存在军事威胁。” | 威胁单位、距离、军力差、城市风险分。 |
| AI 宣战 | “AI 宣战：它认为你在边境和军力上构成威胁。” | 宣战评分、关系变化、军力比、目标城市。 |
| 关系下降 | “关系下降：你的单位靠近了 AI 首都。” | 触发事件、变化值、冷却状态。 |
| AI 造市场 | “AI 正在补充经济。” | 金币库存、净收入、维护费、候选生产评分。 |
| AI 研究弓术 | “AI 正在增强军事能力。” | 当前意图、防御压力、科技候选分。 |

外交面板建议展示：

| 字段 | 示例 |
| --- | --- |
| 当前状态 | 和平 / 紧张 / 战争 |
| 关系值 | `-18` |
| 主要原因 | “边境接近 -15，军力威胁 -8，长期无冲突 +3。” |
| AI 当前意图 | 防御 |
| 最近 5 条关系事件 | 按回合列出原因和变化值。 |
| 战争风险 | 低 / 中 / 高 |

战争风险不需要暴露完整公式，但应能让玩家理解大方向。

## 十五、Worker 化边界

第一版可以先在主线程实现 AI，但接口按 Worker 设计。

| 内容 | Worker 内处理 | 主线程处理 |
| --- | --- | --- |
| 局势分析 | 是 | 生成裁剪快照。 |
| 意图评分 | 是 | 展示评分结果。 |
| 候选行动评分 | 是 | 记录和展示。 |
| 路径搜索 | 可选，复杂后迁移 | 高频 hover 路径可先主线程节流。 |
| Command 生成 | 是 | 给 Command 添加 traceId 后进入 Validator。 |
| Command 验证 | 否 | 必须主线程 Validator。 |
| GameState 修改 | 否 | 必须 Simulation。 |
| 外交状态变更 | 否 | Simulation 根据外交事件结算。 |
| Debug Export | 否 | 主线程整合导出。 |

Worker 请求：

```ts
type AIPlanTurnRequest = {
  aiPlayerId: PlayerId;
  turn: number;
  state: AIReadableState;
  options: {
    maxCommands: number;
    timeBudgetMs: number;
    debugLevel: "none" | "summary" | "full";
  };
};
```

Worker 响应：

```ts
type AIPlanTurnResponse = {
  playerId: PlayerId;
  turn: number;
  primaryIntent: AIIntent;
  secondaryIntent?: AIIntent;
  intentScores: IntentScore[];
  candidateActions: CandidateAction[];
  commands: Command[];
  diplomacyRecommendation?: DiplomacyRecommendation;
  durationMs: number;
  warnings: string[];
};
```

超时策略：

| 情况 | 处理 |
| --- | --- |
| AI 请求超过 800ms | 记录 `AI_TIMEOUT`，使用上一回合意图或保守防御计划。 |
| Worker 崩溃 | 记录错误，AI 本回合只做城市生产补全和结束回合。 |
| 返回过期 turn | 丢弃响应，写入 Worker 调试日志。 |
| 返回非法 Command | 主线程 Validator 拒绝，写入 `rejectedByValidator`。 |

## 十六、调试日志字段

`aiIntentLog` 是第一版必做。建议每个 AI 回合写入一条主日志，关键行动再写子项。

```ts
type AIIntentLogEntry = {
  id: string;
  turn: number;
  playerId: PlayerId;
  phase: "AI_PLAN" | "AI_ACTION";
  primaryIntent: AIIntent;
  secondaryIntent?: AIIntent;
  intentScores: IntentScore[];
  situation: SituationAnalysisSummary;
  chosenCommands: CommandSummary[];
  candidateActions: CandidateActionSummary[];
  diplomacy: {
    state: DiplomacyStatus;
    relationship: number;
    deltaEvents: RelationshipDeltaEvent[];
    warRisk: "low" | "medium" | "high";
    declarationScore?: number;
  };
  rejectedByValidator: RejectedAICommand[];
  visibleThreats: VisibleThreatSummary[];
  resourcePressure: ResourcePressureSummary;
  victoryPressure: VictoryPressureSummary;
  durationMs: number;
  workerRequestId?: string;
  warnings: string[];
};
```

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| `primaryIntent` | 必需 | 本回合 AI 主方向。 |
| `intentScores` | 必需 | 每个意图的基础分、修正项、总分。 |
| `candidateActions` | 必需 | 候选行动和评分，至少保留前 5 个。 |
| `chosenCommands` | 必需 | 最终提交的 Command 摘要。 |
| `rejectedByValidator` | 必需 | AI 输出非法行动时必须记录。 |
| `diplomacy` | 必需 | 当前关系、变化原因、战争风险。 |
| `durationMs` | 必需 | 性能调试和 Worker 迁移依据。 |
| `workerRequestId` | Worker 启用后必需 | 用于关联 Worker 面板。 |
| `warnings` | 建议 | 例如“无合法建城点”“寻路失败”。 |

## 十七、事件与埋点

| 事件 | 触发时机 | 必备字段 |
| --- | --- | --- |
| `ai_intent_selected` | AI 选择主意图。 | `turn`, `intent`, `score`, `topReasons` |
| `ai_command_generated` | AI 生成 Command。 | `commandType`, `reason`, `targetId?`, `score` |
| `ai_command_rejected` | Validator 拒绝 AI Command。 | `commandType`, `errorCode`, `reason`, `traceId` |
| `relationship_changed` | 关系值变化。 | `from`, `to`, `delta`, `reasonCode`, `turn` |
| `diplomacy_state_changed` | 和平/紧张/战争变化。 | `previous`, `next`, `reasonCode`, `turn` |
| `war_declared` | 任一方宣战。 | `attacker`, `defender`, `declarationScore?`, `reasons` |
| `war_risk_changed` | 战争风险等级变化。 | `previous`, `next`, `topFactors` |

这些事件应进入 `EventLog` 或试玩埋点，至少能被 Debug Export 带出。

| 模块 | 验收标准 |
| --- | --- |

## 二十、风险清单

| 风险 | 影响 | 预防措施 |
| --- | --- | --- |
| AI 看起来作弊 | 玩家不信任系统，失败体验差。 | 玩家 UI 只展示 AI 可见信息；开发全知视角明确标记。 |
| AI 决策不可解释 | 难判断是规则问题、AI 问题还是 UI 问题。 | `aiIntentLog`、候选评分、失败 Command 必做。 |
| AI 输出非法 Command | 回合结算混乱或静默失败。 | 主线程 Validator 二次验证，失败写日志并回退。 |
| 宣战太突然 | 玩家觉得不公平。 | 首次接触冷却、战争风险提示、关系变化日志。 |
| AI 过度防御 | 游戏无冲突，30 回合节奏变平。 | 后期提高进攻和科技胜利压力权重。 |
| AI 过度进攻 | 玩家早期被压死。 | 宣战需要军力、距离、冷却和经济条件。 |
| 外交系统膨胀 | 第一版范围失控。 | 不做交易、结盟、议和，只做轻外交状态和宣战。 |
| Worker 通信过重 | AI 本来想降卡顿，反而序列化慢。 | 使用 `AIReadableState` 裁剪快照，记录 payload size。 |
| AI 不可复现 | Debug 和回放失败。 | 固定 RNG、固定排序、CommandLog 记录、禁止依赖真实时间。 |
| 玩家看不懂关系变化 | 外交数值变成黑箱。 | 每次关系变化必须有原因文案和最近事件列表。 |

## 二十一、推荐实现顺序

| 顺序 | 内容 | 退出标准 |
| ---: | --- | --- |
| 1 | 定义 `AIReadableState`、`AIIntentLogEntry`、外交状态结构。 | 能从 `GameState` 生成纯数据 AI 快照。 |
| 2 | 实现局势分析和意图评分。 | Debug 面板可显示每个意图分数和原因。 |
| 3 | 实现科技和生产选择。 | AI 能稳定选择研究和城市生产。 |
| 4 | 实现单位移动、探索、建城。 | AI 能在 30 回合内扩张到第二城。 |
| 5 | 实现轻外交和关系变化。 | 接触、边境压力、攻击能改变关系状态。 |
| 6 | 实现防御、进攻和宣战。 | AI 能在条件满足时宣战，并解释原因。 |
| 7 | 接入 Worker 接口。 | AI 请求有 requestId、耗时、超时和 fallback。 |
| 8 | 加入测试和 Debug Export。 | 固定 seed AI 决策可复现，导出包含 AI 与外交日志。 |
