# 15 美术音频规格与移动端预留

本文档定义第一版 Web 2D/2.5D 文明类原型的美术资产、音频反馈、DPR/高分屏、触控与小屏预留方案。它承接现有文档的核心决策：

| 已定方向 | 对本文件的约束 |
| --- | --- |
| 第一版是桌面浏览器 Web Demo | 美术规格优先服务 12x12 到 20x20 地图、30 回合原型，不为大地图和手机首发过度设计。 |
| PixiJS/WebGL 负责地图画面 | 地形、单位、资源图标、战争迷雾、选中高亮和路径预览进入 WebGL 画布。 |
| React/DOM 负责复杂 UI | 城市面板、科技树、外交面板、Tooltip、百科、调试面板使用 DOM/SVG/React 组件。 |
| GameState 只保存纯规则数据 | 美术资源只通过配置 ID 和资源 key 映射，不进入存档。 |
| Asset Pipeline 使用 manifest + atlas | 地图、单位、资源图标优先进图集；音频和非核心资源懒加载。 |
| 第一版性能目标 60 FPS，低端 30 FPS | 高分屏 DPR、图集尺寸、动画数量必须有预算。 |

一句话结论：

> **第一版采用清晰、轻量、可调试的 2D/2.5D 俯视美术：逻辑 tile 64x64，地图资产进 PixiJS atlas，复杂 UI 使用 DOM/SVG，音频只做关键短反馈，移动端只做输入和布局预留。**

## 一、美术目标

| 目标 | 第一版要求 | 不做什么 |
| --- | --- | --- |
| 可读性优先 | 地形、单位、资源、归属、可行动状态必须一眼分清。 | 不追求复杂写实细节。 |
| 文明感 | 地形有自然差异，城市/建筑/科技图标有时代感。 | 不做完整时代演进美术。 |
| 低成本迭代 | 占位图也要规范命名、尺寸、锚点和图集 key。 | 不临时散落图片路径。 |
| 调试友好 | 资源缺失、图集错误、DPR 问题能在画面和 Debug Panel 暴露。 | 不允许透明空白静默失败。 |
| Web 性能稳定 | 地图高频资源少图集、少滤镜、少实时生成。 | 不在第一版堆粒子、阴影、复杂后处理。 |

## 四、Tile 尺寸建议

| 项目 | 推荐值 | 说明 |
| --- | ---: | --- |
| 逻辑 tile 尺寸 | 64x64 px | 与现有资源管线文档对齐，方便坐标换算和点击命中。 |
| 默认地图尺寸 | 16x16 | 默认可完整展示大部分地图，同时保留拖拽和缩放价值。 |
| 支持地图尺寸 | 12x12 到 20x20 | 第一版性能预算和玩法规则均围绕这个范围。 |
| 最小缩放 | 0.6x | 能看全局局势，资源图标可自动隐藏或缩小。 |
| 最大缩放 | 2.0x | 能看清单位和城市，不暴露贴图过多锯齿。 |
| 默认缩放 | 1.0x 或按容器自适应 | 首屏让首都、初始单位和周围 3 格视野可见。 |
| 地块间距 | 0 或 1px 程序边线 | 优先无缝 tile，网格线用 overlay 控制。 |
| 地块锚点 | 左上角用于坐标，视觉元素居中 | 规则坐标清晰，单位/城市锚点独立。 |

建议第一版使用 **64x64 逻辑 tile + 1x 源图**，在高分屏由 PixiJS/WebGL 缩放处理。若地图贴图显糊，再补 128x128 源图并在 atlas `meta.scale` 或资源命名中明确倍率。

地形可读性检查：

| 检查项 | 标准 |
| --- | --- |
| 0.6x 缩放 | 平原、森林、丘陵、山脉、水域仍能通过轮廓或纹理区分。 |

## 九、图集策略

| Atlas | 内容 | 尺寸上限 | 加载时机 | 备注 |
| --- | --- | ---: | --- | --- |
| `map-core` | 地形、河流、城市基础、选中/可达高亮可选 | 1024x1024，必要时 2048x2048 | critical | 地图首屏必需。 |
| `units-core` | 4 种单位、阵营变体、单位状态角标 | 1024x1024 | critical | 可用 tint 减少重复贴图。 |
| `icons-map` | 资源、攻击、视野、移动力、地块小图标 | 512x512 | critical | PixiJS 与 Tooltip 可共用 key。 |
| `ui-core` | 少量位图 UI 图标 | 512x512 | lazy 或不用 | DOM UI 优先 SVG，不强制进 atlas。 |
| `effects-core` | 战斗/完成/科技反馈帧动画 | 512x512 | 第二版 lazy | 第一版可以用程序动画替代。 |

图集制作约束：

| 约束 | 决策 |
| --- | --- |
| frame key | 必须和资源 key 一致，例如 `terrain.plains`、`unit.scout.player`。 |
| padding | 每个 frame 至少 2px padding，避免 WebGL 缩放采样串色。 |
| 裁切 | 透明边缘可裁切，但要保留 pivot/anchor 元数据或统一锚点。 |
| 倍率 | 第一版先统一 1x；若引入 2x，必须在 manifest 写清 `scale`。 |
| 颜色变体 | 单位阵营优先 tint；地形不使用 tint 改语义。 |
| 资源缺失 | 使用 `missing-texture.png`，并写 `ASSET_MISSING_*` 日志。 |
| 构建检查 | manifest key、atlas frame、配置 ID 必须互相校验。 |

## 十、动画优先级

| 动画 | 目的 | 第一版是否需要 | 实现建议 | 性能注意 |
| --- | --- | --- | --- | --- |
| 地图拖拽惯性 | 提升相机手感 | 可选 | 第一版可先无惯性，保证稳定。 | 避免和点击选择冲突。 |
| 滚轮缩放过渡 | 减少突兀 | 建议 | 100-150ms 插值。 | 输入后下一帧必须有反馈。 |
| 单位移动 | 让移动结果可见 | 必须 | 沿路径线性移动，每格 120-180ms。 | 动画只表现结果，规则先结算。 |
| 选中脉冲 | 强化当前对象 | 建议 | 轻微透明度/边框动画。 | 限制在选中对象。 |
| 可达范围高亮 | 解释移动选择 | 必须 | 静态半透明 overlay，hover 时强化。 | 不每帧重算路径。 |
| 路径预览 | 降低误操作 | 建议 | 鼠标停留节流后更新。 | A* 超过 20ms 要缓存或 Worker。 |
| 战斗反馈 | 说明伤害发生 | 必须 | 攻击闪烁、受击抖动、伤害数字短暂显示。 | 不影响战斗结算顺序。 |
| 生产完成 | 给回合成果反馈 | 建议 | Toast + 城市短闪光。 | 音效和视觉可同步。 |
| 科技完成 | 强化成长 | 建议 | 科技图标高亮 + Toast。 | DOM 动画即可。 |
| 胜利/失败 | 结束局反馈 | 必须 | 复盘面板 + 音效。 | 不做复杂全屏特效。 |
| 粒子特效 | 提升表现 | 第二版 | 小粒子、资源收集、建筑完成。 | 第一版先不常驻。 |

动画边界：

| 边界 | 说明 |
| --- | --- |
| 规则不等动画 | `Simulation` 先产出结果，动画只播放状态 diff。 |
| 动画可跳过 | 读档、快速回合、Debug 跳回合必须能跳过动画。 |
| 动画不进存档 | 当前动画进度不写 `GameState`。 |
| 低性能降级 | FPS 低于 30 时，减少粒子和过渡，只保留必要反馈。 |

## 十一、音频方向

第一版音频目标不是做完整配乐，而是让关键操作有确认感、完成感和风险提示。音频默认延后加载，并在用户首次交互后解锁 AudioContext。

| 类型 | 第一版决策 |
| --- | --- |
| 音效数量 | 8-12 个短 SFX。 |
| 单个时长 | UI 点击 0.05-0.2s，事件反馈 0.3-1.2s。 |
| 格式 | OGG 优先；如目标浏览器需要再补 MP3 fallback。 |
| 音量设置 | `masterVolume`、`sfxVolume`、`musicVolume` 进入 Settings/LocalStorage。 |
| 播放策略 | 音效失败不阻塞玩法，写入 Debug Event。 |
| 背景音乐 | 可选 1 条低存在感循环；第一版可以先只做环境底噪或不做。 |

| 结束回合 | `END_TURN` 成功 | 翻页/钟声 | 必须 | `sfx.turnEnd` |
| 自动存档成功 | 存档完成 | 很轻提示或无声 | 可选 | `sfx.saveComplete` |
| 存档失败 | 存档失败 | 警告短音 | 必须 | `sfx.saveFailed` |
| AI 宣战 | 外交状态进入战争 | 紧张警报 | 必须 | `sfx.warDeclared` |
| 胜利 | 胜利面板出现 | 短胜利动机 | 必须 | `sfx.victory` |
| 失败 | 失败/被征服 | 低沉结束音 | 必须 | `sfx.defeat` |

音频实现注意：

| 风险 | 处理 |
| --- | --- |
| 浏览器限制自动播放 | 第一次用户点击后初始化音频并预热关键短音效。 |
| 音频和动画不同步 | 以 `EventLog` 或状态 diff 触发，不从 PixiJS 动画内部触发规则。 |
| 重复音效刺耳 | 同类音效设置 80-120ms 最小间隔，批量事件做合并提示。 |
| 用户不想听声音 | 设置里提供静音，默认音量克制。 |

## 十三、DPR 与高分屏策略

| 项目 | 第一版策略 | 说明 |
| --- | --- | --- |
| DPR 上限 | 默认 `min(window.devicePixelRatio, 2)` | 避免 3x/4x 高分屏让 canvas 过大。 |
| 低性能降级 | FPS 持续低于 30 时可降到 DPR 1.5 或 1 | 需要在 Debug Panel 可见。 |
| Canvas 尺寸 | CSS 尺寸和实际 drawing buffer 分离 | resize 时节流更新。 |
| 贴图倍率 | 第一版 1x 为主，必要时补 2x | 不混用未标记倍率资源。 |
| 文字渲染 | 地图小字尽量少，文字走 DOM | 避免 PixiJS 小字在高分屏/缩放下模糊。 |
| 图标清晰度 | UI 图标 SVG 优先 | DOM 图标不受 atlas 倍率限制。 |
| 截图测试 | Playwright 分别测 DPR 1 和 DPR 2 | 检查 canvas 非空、资源无错位。 |

DPR 决策伪代码：

```ts
function chooseRenderResolution(devicePixelRatio: number, perfMode: "auto" | "quality" | "battery") {
  if (perfMode === "battery") return 1;
  if (perfMode === "quality") return Math.min(devicePixelRatio, 2);
  return Math.min(devicePixelRatio, 2);
}
```

## 十四、响应式与小屏策略

第一版不以手机为主，但不能把未来小屏适配堵死。建议设定三个布局断点：

| 宽度 | 布局策略 | 第一版支持程度 |
| ---: | --- | --- |
| `>= 1200px` | 桌面完整布局：顶部栏、左事件栏、右详情面板、底部行动栏 | 必须 |
| `900-1199px` | 笔记本紧凑布局：右面板变窄，事件栏可折叠 | 必须 |
| `600-899px` | 小屏预览布局：右面板改底部抽屉，部分面板全屏 | 预留 |
| `< 600px` | 手机布局：地图优先，面板全屏/底抽屉，隐藏复杂科技树 | 不作为第一版验收 |

小屏信息优先级：

| 优先级 | 保留内容 | 可折叠内容 |
| --- | --- | --- |
| 高 | 地图、当前回合、核心资源、结束回合、当前选择对象 | 事件日志详情。 |
| 中 | 当前单位动作、城市生产、科技选择、Tooltip 详情 | 胜利详情、百科长文。 |
| 低 | Debug Panel、完整外交原因、完整科技树 | 大部分调试 overlay。 |

## 二十、风险清单

| 风险 | 表现 | 严重度 | 预防措施 |
| --- | --- | --- | --- |
| 地形只靠颜色区分 | 色弱玩家或缩放后看不懂地图 | 高 | 加纹理、轮廓和 Tooltip；资源不要只靠颜色。 |
| 图集过大 | 低端设备加载慢或 WebGL context lost | 高 | 第一版 atlas 控制在 1024/2048 以内，critical 2-3 个。 |
| DPR 过高 | 高分屏 canvas 内存和 fill-rate 压力过大 | 高 | DPR 默认封顶 2，低性能可降级到 1。 |
| 单位/城市遮挡资源 | 玩家看不见地块收益 | 中 | 调整锚点和层级，资源图标可在 hover/选中时显示。 |
| UI 图标和地图图标语义不一致 | 玩家学习成本增加 | 中 | 统一资源 key 和图标源，配置表引用同一语义。 |
| 动画驱动规则 | 读档、跳回合、回放出现不一致 | 高 | 规则先结算，动画只表现结果。 |
| 音频自动播放失败 | 第一声无反馈或报错 | 中 | 首次交互解锁音频，失败只写日志不阻塞。 |
| 音效过多刺耳 | 回合结算时声音堆叠 | 中 | 同类音效节流，批量事件合并播放。 |
| 手机布局提前做重 | 拖慢第一版桌面原型 | 中 | 只做输入和布局预留，不做完整手机版。 |
| Hover 信息无法触控访问 | 未来手机不可用 | 中 | Tooltip 必须支持点击/焦点/长按替代。 |
| 占位图太随意 | 后续替换成本高 | 中 | 占位图也按正式尺寸、key、锚点和图集规则制作。 |
| 美术文件中文命名 | 构建/CDN/跨平台风险 | 低 | 运行时资源路径使用 ASCII。 |

## 二十一、第一版实施顺序

| 顺序 | 任务 | 验收 |
| ---: | --- | --- |
| 1 | 确定 tile、单位、资源图标尺寸和 key | `terrain.*`、`unit.*`、`resource.*` key 表完整。 |
| 2 | 制作或生成占位 `map-core`、`units-core`、`icons-map` | PixiJS 能通过 manifest 加载并绘制默认地图。 |
| 3 | 接入战争迷雾、选中高亮、可达范围 | 三态迷雾和行动范围可读。 |
| 4 | 接入 UI SVG 图标和建筑/科技图标 | 顶栏、城市面板、科技树不缺核心图标。 |
| 5 | 实现基础动画：单位移动、战斗反馈、完成提示 | 动画可跳过，不影响 GameState。 |
| 6 | 接入 8-12 个 SFX 和音量设置 | 关键事件有反馈，首次交互解锁音频。 |
| 7 | 实现 DPR 策略和 Debug 显示 | Debug Panel 显示 DPR、纹理数、缺失资源。 |
| 8 | 做 DPR 1/2、缩放 0.6/2.0、缺失资源冒烟检查 | Playwright 或人工检查通过。 |
| 9 | 加移动端预留：Pointer Events、底部抽屉断点、按钮尺寸 | 手机打开不崩，核心按钮可点击。 |

## 二十二、结论

第一版美术音频不应该追求“完整商业化表现”，而应该优先保证三件事：

| 重点 | 推荐决策 |
| --- | --- |
| 地图可读 | 64x64 逻辑 tile，地形/单位/资源用 atlas 管理，战争迷雾和高亮由 PixiJS 表现。 |
| 反馈明确 | 单位移动、战斗、生产完成、科技完成、结束回合、失败操作都有视觉或音频反馈。 |
| Web 稳定 | DPR 封顶、少图集、短音频、动画可降级，移动端只做输入和布局预留。 |

最终落地路线：

> **先用规范占位资产跑通 WebGL 地图和 DOM UI，再逐步替换正式地形、单位、城市、科技/建筑图标与短音效。所有资产都通过 manifest、atlas 和资源 key 管理，避免美术替换时破坏规则、存档和测试。**
