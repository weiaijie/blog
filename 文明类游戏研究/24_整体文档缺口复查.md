## 五、开工前必须再补的最小内容

如果现在准备进入代码阶段，建议补足下面 5 个最小规则，不一定都要做成大文档，但必须有明确记录。

| 必补项 | 最小规则 |
| --- | --- |
| 许可证登记 | 每个第三方库、字体、音效、图标、图片都登记来源、许可证、是否可商用、是否需要署名。 |
| 隐私与遥测 | 第一版不默认上传玩家数据；Debug Export 由玩家主动导出；公开试玩前写清远程日志策略。 |
| 导入安全 | 导入 Save/Debug/Config JSON 必须做 schema 校验、大小限制、版本校验，失败不能污染当前存档。 |
| 调参流程 | 每次修改 `balance.ts`、单位、科技、建筑、AI 权重，都记录改动原因和对局指标。 |
| 地图测试集 | 至少准备小图、默认图、压力图、边界图、坏数据图，分别验证玩法、性能和错误处理。 |

## 七、最终判断

目前文档已经达到可以进入 Web 原型设计和技术骨架搭建的程度。核心方向不再缺：玩法闭环、WebGL、引擎选型、地图规模、回合计算、存档、调试、部署都已经覆盖。

真正剩下的缺口是三类：

1. 公开试玩前的合规和隐私边界。
2. 数值长期迭代需要的配置调参流程。
3. 进入代码阶段需要的工程质量门禁。

这些不会推翻现有架构，但越早补越能减少后期返工。
