# 11 资源管线与部署方案

本文档负责 Web 原型的资源组织、加载、缓存和发布方案。它承接 `07_Web游戏引擎选型调研.md`、`08_工程架构设计.md`、`09_玩法规则规格表.md` 的结论：第一版采用 `TypeScript + Vite + PixiJS/WebGL + React DOM UI`，PixiJS 负责地图渲染，React/DOM 负责复杂 UI，规则与存档保持纯数据化。

核心目标：第一版资源管线要足够轻，能支持 30 回合 Web Demo 快速试玩；同时从一开始保留 manifest、版本号、图集、缺失资源兜底和构建校验，避免后期资源扩张时失控。

## 一、资源管线结论

| 方向 | 第一版推荐决策 | 原因 |
| --- | --- | --- |
| 资源组织 | 按 `assets/`、`config/`、`audio/`、`fonts/`、`generated/` 分层 | 区分美术资源、规则配置、构建产物和运行时代码。 |
| 地图资源 | 地形、资源图标、单位优先进入 texture atlas | 减少 WebGL 纹理切换，方便 PixiJS 批量渲染。 |
| UI 图标 | 小图标可单独 SVG/PNG，常用图标也可进 UI atlas | DOM UI 可直接用 SVG，地图 overlay 图标优先进 atlas。 |
| 配置表 | 使用 JSON 或 TypeScript 数据表，构建时校验 schema | 单位、建筑、科技、地形尽量数据驱动。 |
| 加载入口 | 使用统一 `AssetManager` 读取 `asset-manifest.json` | 避免渲染层到处硬编码路径。 |
| 首屏策略 | 先加载启动 UI、核心 atlas、核心配置；非关键音频延后加载 | 3 秒内看到加载进度或主界面。 |
| 缓存策略 | 构建产物带 hash，manifest 和 HTML 使用短缓存 | 避免玩家拿到旧 manifest 指向新旧混杂资源。 |
| 部署方式 | Vite 静态构建，优先部署到静态站点/CDN | Web Demo 的优势是发链接即可试玩。 |
| 错误日志 | 前端捕获资源加载、WebGL、存档、Worker、运行时错误 | 试玩阶段必须能定位资源缺失和构建版本问题。 |
| CI 构建 | lint、typecheck、test、build、manifest 校验、轻量冒烟 | 防止坏资源和错误配置进入试玩版本。 |

## 二、资源分类表

| 分类 | 示例 | 第一版范围 | 存放建议 | 加载优先级 |
| --- | --- | --- | --- | --- |
| 地形贴图 | 平原、森林、丘陵、山脉、水域、河流边缘 | 必须 | `public/assets/atlas/map-core.png` + `.json` | 高 |
| 战争迷雾 | 未探索、已探索不可见、当前可见遮罩 | 必须 | 可先用程序绘制，后续进 atlas 或 shader | 高 |
| 单位 Sprite | 侦察兵、战士、建造者、弓手 | 必须 | `public/assets/atlas/units-core.png` + `.json` | 高 |
| 资源图标 | 粮食、生产力、金币、科技、特殊资源占位 | 必须 | `public/assets/atlas/icons-map.png` + `.json` | 高 |
| 建筑图标 | 粮仓、工坊、市场、学院、城墙 | 必须 | `public/assets/icons/buildings/` 或 UI atlas | 中 |
| 科技图标 | 农业、采矿、侦察、弓术、工具、书写等 | 必须 | `public/assets/icons/techs/` 或 UI atlas | 中 |
| UI 图标 | 结束回合、保存、读档、调试、关闭、警告 | 必须 | SVG 组件或 `public/assets/icons/ui/` | 高 |
| 地图装饰 | 城市边界、可移动格、高亮、路径箭头 | 必须 | 程序绘制 + 少量 atlas sprite | 高 |
| 音频 | 回合结束、生产完成、科技完成、战斗、错误提示 | 建议 | `public/audio/sfx/` | 低，交互后加载 |
| 字体 | 中文 UI 字体、数字字体、图标字体可选 | 建议 | 优先系统字体，定制字体第二版 | 中 |
| 规则配置 | 地形、单位、建筑、科技、战斗公式参数 | 必须 | `src/game/config/*.ts` 或 `public/config/*.json` | 高 |
| 调试地图 | 固定种子、固定地形、固定单位布置 | 必须 | `src/game/debug/maps/*.json` | 高 |
| 本地化文本 | Tooltip、按钮、日志模板、错误说明 | 建议 | `src/i18n/zh-CN.ts` 或 JSON | 中 |
| 构建元信息 | `buildVersion`、commit、构建时间、资源版本 | 必须 | `public/build-info.json` 或注入环境变量 | 高 |

说明：

| `public/build-info.json` | 用于错误日志、存档版本、试玩版本识别。 |

## 四、命名规范

### 1. 文件命名

| 类型 | 命名格式 | 示例 |
| --- | --- | --- |
| 地图图集 | `map-{scope}.png/json` | `map-core.png`、`map-river.json` |
| 单位图集 | `units-{scope}.png/json` | `units-core.png` |
| 地图图标图集 | `icons-map.png/json` | `icons-map.png` |
| UI 图标 | `ui-{action}-{state}.svg` | `ui-end-turn-default.svg` |
| 科技图标 | `tech-{techId}.png/svg` | `tech-archery.png` |
| 建筑图标 | `building-{buildingId}.png/svg` | `building-granary.png` |
| 音效 | `sfx-{event}-{variant}.ogg` | `sfx-turn-end-01.ogg` |
| 音乐 | `music-{scene}-{loop}.ogg` | `music-map-loop.ogg` |
| 调试地图 | `map-debug-{size}-{name}.json` | `map-debug-16x16-alpha.json` |
| 配置表 | `{domain}.ts/json` | `terrain.ts`、`techs.json` |

### 2. 资源 key 命名

| 资源 | key 格式 | 示例 |
| --- | --- | --- |
| 地形 | `terrain.{terrainId}` | `terrain.plains` |
| 地形特征 | `feature.{featureId}` | `feature.forest` |
| 单位 | `unit.{unitId}.{owner?}` | `unit.scout.player` |
| 资源图标 | `resource.{resourceId}` | `resource.food` |
| 建筑图标 | `building.{buildingId}` | `building.workshop` |
| 科技图标 | `tech.{techId}` | `tech.writing` |
| UI 图标 | `ui.{name}` | `ui.endTurn` |
| 音效 | `sfx.{event}` | `sfx.techComplete` |

约束：

| 约束 | 说明 |
| --- | --- |
| 资源 key 不写文件后缀 | 渲染层只依赖 key，不依赖路径。 |
| GameState 不保存资源路径 | GameState 保存 `terrainId`、`unitType`、`buildingId`，渲染层映射到资源 key。 |
| 配置 ID 与资源 key 对齐 | `unit.scout` 对应配置里的 `unitId = "scout"`，减少人工映射错误。 |
| 禁止中文文件名进入构建资源路径 | 文档可以中文，运行时资源建议 ASCII，降低跨平台和 CDN 风险。 |

## 五、Texture Atlas 方案

### 1. 第一版 atlas 分组

| Atlas | 内容 | 建议尺寸 | 说明 |
| --- | --- | ---: | --- |
| `map-core` | 平原、森林、丘陵、山脉、水域、河流、道路占位 | 1024x1024 以内 | 地图渲染高频，必须优先加载。 |
| `units-core` | 侦察兵、战士、建造者、弓手，玩家/AI 两套色或 tint | 1024x1024 以内 | 第一版可用同图不同 tint 区分阵营。 |
| `icons-map` | 粮食、生产力、金币、科技、攻击、视野、移动力 | 512x512 以内 | 地图 overlay 和 Tooltip 共用。 |
| `ui-core` | 回合、保存、读档、警告、调试、关闭 | 可选 | 若 UI 使用 SVG 组件，可不进 atlas。 |

### 2. Atlas 数据要求

| 字段 | 要求 |
| --- | --- |
| `frames` | 每个 frame 必须有稳定 key，例如 `terrain.plains`。 |
| `meta.image` | 指向同目录 PNG/WebP。 |
| `meta.scale` | 第一版固定 `"1"`，高分屏第二版再扩展。 |
| `tags` | 可选，用于分类加载和调试。 |
| `version` | 图集版本，配合 manifest 校验。 |

### 3. 图集制作原则

| 原则 | 决策 |
| --- | --- |
| 地图 tile 尺寸 | 第一版建议逻辑 tile 64x64，实际可按 1x 图绘制。 |
| 单位 Sprite 尺寸 | 第一版建议 64x64 或 96x96，保证缩放后仍清晰。 |
| 图集边距 | 每个 sprite 留 1-2px padding，避免 WebGL 采样串色。 |
| 颜色变体 | 玩家/AI 单位优先用 tint 或少量色板，不急着做多套资源。 |
| 占位策略 | 没有美术时使用清晰占位图，不使用透明空白。 |
| 后续升级 | 第二版再考虑 WebP/AVIF、multi-pack、normal map 或 shader 特效。 |

## 六、配置表方案

第一版建议规则配置先放在 `src/game/config/*.ts`，因为 TypeScript 能直接给出类型错误。若后续需要策划表格或在线编辑器，再迁移到 JSON/CSV 并加入 schema 校验。

| 配置表 | 内容 | 是否必须 | 关联资源 |
| --- | --- | --- | --- |
| `terrain.ts` | 地形产出、移动消耗、防御加成、通行、可建城 | 必须 | `terrain.{id}`、`feature.{id}` |
| `resources.ts` | 粮食、生产力、金币、科技等显示名、图标、颜色 | 必须 | `resource.{id}` |
| `units.ts` | 成本、生命、攻击、射程、移动、视野、维护 | 必须 | `unit.{id}` |
| `buildings.ts` | 成本、效果、前置科技、图标 | 必须 | `building.{id}` |
| `techs.ts` | 成本、前置、解锁、图标、路线 | 必须 | `tech.{id}` |
| `audioEvents.ts` | 事件到音效 key 的映射 | 建议 | `sfx.{event}` |
| `tutorialSteps.ts` | 前 5 分钟引导步骤、触发条件、文案 key | 建议 | UI 文本 |
| `balance.ts` | 人口成长、维护费、胜利分数等全局参数 | 必须 | 无 |

配置表约束：

| 约束 | 说明 |
| --- | --- |
| ID 稳定 | 存档里会保存 `unitType`、`techId`、`buildingId`，上线后不要随意改 ID。 |
| 数值可解释 | 每个核心公式都要能在 EventLog 或 Tooltip 展示。 |
| 配置引用必须校验 | 科技解锁建筑、建筑前置科技、单位图标 key 必须在构建或启动时检查。 |
| 存档版本绑定配置 | 存档带 `buildVersion` 和 `schemaVersion`，配置大改时需要迁移策略。 |

## 七、Asset Manifest 示例

`asset-manifest.json` 是运行时资源入口。PixiJS 可以使用资源别名加载贴图；项目自己的 `AssetManager` 负责把 manifest 转成 PixiJS 和 DOM UI 都能使用的资源表。

```json
{
  "schemaVersion": 1,
  "assetVersion": "0.1.0-alpha.3",
  "buildVersion": "2026.05.22-alpha",
  "generatedAt": "2026-05-22T00:00:00.000Z",
  "requiredClientSchema": 1,
  "bundles": [
    {
      "name": "boot",
      "priority": "critical",
      "assets": [
        {
          "key": "placeholder.missingTexture",
          "type": "image",
          "url": "/assets/placeholders/missing-texture.png"
        },
        {
          "key": "build.info",
          "type": "json",
          "url": "/build-info.json"
        }
      ]
    },
    {
      "name": "map-core",
      "priority": "critical",
      "assets": [
        {
          "key": "atlas.mapCore",
          "type": "atlas",
          "url": "/assets/atlas/map-core.json",
          "image": "/assets/atlas/map-core.png"
        },
        {
          "key": "atlas.iconsMap",
          "type": "atlas",
          "url": "/assets/atlas/icons-map.json",
          "image": "/assets/atlas/icons-map.png"
        }
      ]
    },
    {
      "name": "units-core",
      "priority": "critical",
      "assets": [
        {
          "key": "atlas.unitsCore",
          "type": "atlas",
          "url": "/assets/atlas/units-core.json",
          "image": "/assets/atlas/units-core.png"
        }
      ]
    },
    {
      "name": "audio-sfx",
      "priority": "lazy",
      "assets": [
        {
          "key": "sfx.turnEnd",
          "type": "audio",
          "url": "/audio/sfx/sfx-turn-end-01.ogg"
        },
        {
          "key": "sfx.techComplete",
          "type": "audio",
          "url": "/audio/sfx/sfx-tech-complete-01.ogg"
        }
      ]
    }
  ],
  "fallbacks": {
    "image": "placeholder.missingTexture",
    "atlasFrame": "placeholder.missingTexture",
    "audio": null
  }
}
```

Manifest 校验规则：

| 校验项 | 失败处理 |
| --- | --- |
| `schemaVersion` 不支持 | 阻止进入游戏，提示版本不兼容。 |
| critical bundle 加载失败 | 显示错误页，允许重试和复制错误信息。 |
| lazy bundle 加载失败 | 写入错误日志，禁用对应音效或非核心表现。 |
| key 重复 | CI 直接失败。 |
| 配置引用不存在的资源 key | CI 直接失败。 |
| 文件不存在或大小为 0 | CI 直接失败。 |

## 八、加载流程

### 1. 启动加载流程

```text
加载 HTML/JS/CSS
  -> 读取 build-info.json
  -> 读取 asset-manifest.json
  -> 校验 manifest schema 和版本
  -> 加载 boot bundle
  -> 初始化 React 壳和加载界面
  -> 加载 map-core、units-core、核心配置
  -> 初始化 PixiJS Application
  -> 创建/读取 GameState
  -> 首次渲染地图
  -> 后台懒加载音频、非核心图标、百科文本
```

### 2. 加载进度展示

| 阶段 | UI 展示 | 技术要求 |
| --- | --- | --- |
| 读取 manifest | “正在检查版本” | 失败要能提示刷新或清缓存。 |
| 加载核心资源 | 百分比 + 当前 bundle 名称 | 统计已完成资源数和字节数，字节数拿不到时按资源数。 |
| 初始化渲染 | “正在准备地图” | WebGL 初始化失败时显示 fallback 说明。 |
| 读档恢复 | “正在恢复存档” | 读档失败不能白屏，要允许新开局。 |
| 懒加载 | 不阻塞主界面 | 音频失败只静默降级并写日志。 |

### 3. AssetManager 职责

| 职责 | 说明 |
| --- | --- |
| 读取 manifest | 统一资源入口，禁止业务代码散落 URL。 |
| 加载 bundle | 支持 critical 和 lazy 两类资源。 |
| 暴露资源 key | 渲染层通过 key 获取 texture 或 frame。 |
| 提供 fallback | 缺失贴图返回占位纹理，缺失音频不播放。 |
| 记录错误 | 资源 URL、key、bundle、buildVersion、浏览器信息。 |
| 清理资源 | 读档、切图集或退出时释放非核心资源。 |

## 九、缓存策略

| 资源 | 推荐缓存 | 原因 |
| --- | --- | --- |
| `index.html` | `no-cache` 或短缓存 | HTML 要尽快拿到新入口。 |
| `asset-manifest.json` | `no-cache` 或短缓存 | manifest 决定资源版本，不能长期旧。 |
| `build-info.json` | `no-cache` 或短缓存 | 错误日志和存档版本依赖它。 |
| Vite JS/CSS 构建产物 | 长缓存 + 文件 hash | 内容变更会产生新文件名，适合 CDN 缓存。 |
| atlas PNG/JSON | 长缓存 + 文件 hash 或版本路径 | 体积大，适合缓存；必须避免旧 manifest 指新资源。 |
| 音频 | 长缓存 + 文件 hash | 体积较大，变化少。 |
| 配置 JSON | 短缓存或随构建 hash | 规则配置影响存档和数值，更新要谨慎。 |
| IndexedDB 存档 | 不走 HTTP 缓存 | 由 StorageService 管理 schema 迁移。 |

关键原则：

| 原则 | 说明 |
| --- | --- |
| manifest 不能长期缓存 | 否则玩家可能加载旧资源列表。 |
| 大资源必须 hash 或版本化 | 否则 CDN 和浏览器可能混用旧贴图。 |
| 规则配置更新要关联 `buildVersion` | 防止旧存档用新配置产生不可解释结果。 |
| 第一版不强求离线 PWA | 可以先本地存档；Service Worker 第二版再评估。 |
| 若引入 Service Worker | 必须提供版本升级和缓存清理按钮，避免试玩版资源卡死。 |

## 十、部署流程

| 步骤 | 操作 | 产物/检查 |
| --- | --- | --- |
| 1 | 安装依赖 | lockfile 固定依赖版本。 |
| 2 | 运行 lint/typecheck | 发现 TypeScript 和格式问题。 |
| 3 | 运行单元测试 | 覆盖配置校验、Simulation、Storage、AssetManager。 |
| 4 | 生成或校验 manifest | 检查 key 唯一、文件存在、critical bundle 完整。 |
| 5 | 运行 `vite build` | 生成静态产物。 |
| 6 | 生成 `build-info.json` | 写入 version、commit、buildTime、assetVersion。 |
| 7 | 本地预览构建结果 | 使用 Vite preview 或静态服务器。 |
| 8 | Playwright 冒烟 | 打开页面、加载地图、结束回合、保存读档。 |
| 9 | 上传静态产物 | 部署到静态站点/CDN。 |
| 10 | 发布后健康检查 | 校验 manifest、核心资源、页面加载、错误日志。 |

推荐 `build-info.json`：

```json
{
  "appVersion": "0.1.0-alpha.3",
  "assetVersion": "0.1.0-alpha.3",
  "schemaVersion": 1,
  "commit": "local-dev",
  "buildTime": "2026-05-22T00:00:00.000Z",
  "environment": "preview"
}
```

## 十一、CI 构建建议

| Job | 检查内容 | 第一版是否必须 |
| --- | --- | --- |
| `lint` | ESLint/格式检查 | 必须 |
| `typecheck` | TypeScript 类型 | 必须 |
| `unit-test` | Simulation、Validator、配置、AssetManager | 必须 |
| `manifest-check` | 资源 key、文件存在、重复、fallback | 必须 |
| `build` | Vite 静态构建 | 必须 |
| `preview-smoke` | 构建后启动静态服务，跑 Playwright 冒烟 | 建议 |
| `bundle-report` | JS、atlas、音频体积统计 | 建议 |
| `deploy-preview` | 每次 PR 自动生成试玩链接 | 第二阶段 |

CI 失败条件建议：

| 条件 | 阈值 |
| --- | --- |
| critical 资源缺失 | 任何一个缺失都失败。 |
| manifest key 重复 | 任何重复都失败。 |
| 配置引用不存在资源 | 任何一个引用缺失都失败。 |
| 首屏 JS 体积明显超预算 | 第一版先设 warning，后续再 hard fail。 |
| Playwright 无法看到地图 canvas | 失败。 |
| 保存读档冒烟失败 | 失败。 |

## 十二、缺失资源兜底

| 缺失类型 | 兜底表现 | 日志 |
| --- | --- | --- |
| 地形贴图缺失 | 显示紫黑格或明确占位 tile，并标注 key | `ASSET_MISSING_TEXTURE` |
| 单位贴图缺失 | 显示占位单位图标和单位类型文字 | `ASSET_MISSING_UNIT_SPRITE` |
| 资源图标缺失 | 显示通用资源占位图标 | `ASSET_MISSING_ICON` |
| 音效缺失 | 不播放音效，不阻塞交互 | `ASSET_MISSING_AUDIO` |
| 字体加载失败 | 使用系统字体栈 | `ASSET_FONT_FALLBACK` |
| 配置缺字段 | 开发环境抛错，生产环境阻止开局 | `CONFIG_SCHEMA_INVALID` |
| manifest 不兼容 | 显示版本错误页，提示刷新 | `ASSET_MANIFEST_INCOMPATIBLE` |
| WebGL 初始化失败 | 显示错误页或 Canvas 2D 极简 fallback 提示 | `RENDER_CONTEXT_FAILED` |

兜底规则：

| 规则 | 说明 |
| --- | --- |
| 不允许透明静默失败 | 缺贴图必须在画面或调试面板可见。 |
| critical 资源失败不进局 | 地图核心 atlas、单位 atlas、核心配置缺失时不能进入游戏。 |
| lazy 资源失败可继续 | 音效、百科图标、非核心 UI 图标失败时不阻塞。 |
| 错误可复制 | 错误页提供 buildVersion、assetVersion、资源 key、URL。 |

## 十三、错误日志与观测

第一版至少做本地调试日志；如果部署给外部试玩，再接入远程日志服务。

| 错误类型 | 捕获位置 | 记录字段 |
| --- | --- | --- |
| 资源加载失败 | `AssetManager` | key、url、bundle、status、buildVersion。 |
| WebGL context lost | `RenderEngine` canvas 事件 | renderer、地图大小、单位数、显存压力线索。 |
| JS 运行时错误 | `window.onerror` / React error boundary | message、stack、route、buildVersion。 |
| Promise 未处理 | `unhandledrejection` | reason、stack、当前阶段。 |
| Worker 错误 | `WorkerClient` | requestId、type、duration、payload 摘要。 |
| 存档失败 | `StorageService` | schemaVersion、saveId、错误码、容量线索。 |
| manifest 版本不兼容 | 启动流程 | client schema、manifest schema、assetVersion。 |

建议调试导出包含：

| 数据 | 用途 |
| --- | --- |
| `build-info.json` | 确认试玩版本。 |
| `asset-manifest.json` 摘要 | 确认资源版本。 |
| GameState 摘要 | 复现当前局。 |
| 最近 200 条 EventLog | 定位玩法和资源加载问题。 |
| 性能快照 | FPS、frame time、单位数、tile 数、texture 数。 |
| 浏览器信息 | 判断 WebGL、音频、存储兼容问题。 |

## 十四、性能风险与预算

| 风险 | 表现 | 预防措施 |
| --- | --- | --- |
| atlas 太多 | 地图拖拽时掉帧 | 第一版控制 atlas 数量，地图高频资源合并。 |
| 单个纹理过大 | 低端设备加载失败或 context lost | 第一版 atlas 控制在 1024/2048 以内，逐步压测。 |
| 每格独立 DOM | 地图滚动卡顿 | 地图内容全部 PixiJS，DOM 只做面板和少量 overlay。 |
| 资源未预加载 | 首次打开面板或战斗卡顿 | critical/lazy 分层，常用资源进入 critical。 |
| 音频首播延迟 | 第一次点击后音效慢 | 用户首次交互后解锁 audio context 并预热短音效。 |
| 字体体积大 | 首屏变慢和文字跳动 | 第一版优先系统字体，定制字体延后。 |
| source map 泄露 | 生产源码暴露 | 公开试玩可关闭公开 source map，内部预览保留受控 source map。 |
| 缓存混乱 | 玩家加载旧图集或旧配置 | HTML/manifest 短缓存，hashed assets 长缓存。 |
| 配置与存档不兼容 | 读档后数值异常 | 存档记录 buildVersion，配置大改时迁移或阻止读档。 |

第一版资源预算建议：

| 指标 | 目标 |
| --- | --- |
| 首屏 critical 资源 | 尽量小于 5 MB |
| 首屏看到加载界面 | 1 秒内 |
| 看到可交互地图 | 普通桌面网络 3 秒内为目标 |
| Atlas 数量 | critical 阶段 2-3 个 |
| 音频 | 第一版 5-8 个短 SFX，延后加载 |
| 字体 | 默认系统字体，避免首屏字体下载 |

## 十五、静态部署方案

### 1. 推荐环境

| 环境 | 用途 | 策略 |
| --- | --- | --- |
| local | 本地开发 | Vite dev server，资源可不 hash。 |
| preview | 给团队试玩 | 每次构建独立 URL，保留 source map 或调试导出。 |
| production | 稳定试玩版本 | hashed assets、错误日志、禁用调试入口或隐藏。 |

### 2. Vite 注意事项

| 项目 | 决策 |
| --- | --- |
| `base` | 如果部署到子路径，必须配置 Vite `base`，避免资源 404。 |
| public 资源 | `public/` 下资源以根路径访问；manifest 中路径要考虑部署 base。 |
| 构建 hash | Vite 构建产物默认适合 hash 缓存；自定义 atlas 也应版本化。 |
| 环境变量 | 使用 `VITE_APP_VERSION`、`VITE_ASSET_VERSION` 注入版本。 |
| 预览测试 | 每次部署前用静态预览跑一次，不只测 dev server。 |

### 3. 发布检查清单

| 检查项 | 通过标准 |
| --- | --- |
| 页面加载 | 无白屏，能看到加载进度。 |
| WebGL | canvas 创建成功，地图可拖拽缩放。 |
| Manifest | critical bundles 全部加载成功。 |
| 存档 | 保存、刷新、读档恢复。 |
| 缓存 | 新版本发布后能拿到新 manifest。 |
| 错误页 | 断开某个非核心资源时有可解释日志。 |
| 版本信息 | 调试面板显示 appVersion、assetVersion、commit。 |

## 十六、与其他系统的边界

| 系统 | 资源管线提供 | 不负责 |
| --- | --- | --- |
| RenderEngine | texture、atlas frame、缺失贴图、资源加载状态 | 决定单位位置、地形产出、胜负。 |
| React UI | 图标 URL、音频播放入口、加载进度、错误信息 | 直接修改资源 manifest。 |
| Simulation | 配置表、稳定 ID、版本信息 | 加载图片、播放音效。 |
| StorageService | buildVersion、assetVersion、配置版本 | 保存纹理、音频、DOM 状态。 |
| Worker | 轻量配置数据、地图规则参数 | 加载 PixiJS texture 或访问 DOM。 |

## 十七、第一版实施顺序

| 顺序 | 工作 | 验收 |
| --- | --- | --- |
| 1 | 建立资源目录和命名规范 | 新资源能按规则放置。 |
| 2 | 编写 `asset-manifest.json` 初版 | boot、map-core、units-core 可被读取。 |
| 3 | 实现 `AssetManager` | 可加载 critical bundle，失败有 fallback。 |
| 4 | 接入 PixiJS atlas | 地形、单位、资源图标通过 key 渲染。 |
| 5 | 接入配置表校验 | 单位、科技、建筑引用资源 key 不会漏。 |
| 6 | 增加加载界面 | 显示 bundle 进度和错误。 |
| 7 | 增加 build-info | 调试面板能显示版本。 |
| 8 | 增加 CI manifest 校验 | 缺文件、重复 key、配置引用错误会失败。 |
| 9 | 部署 preview | 静态 URL 可试玩并可保存读档。 |
| 10 | 增加错误日志导出 | 资源缺失、WebGL、存档错误可复制给开发者。 |
