# 13 UI 新手引导与信息透明

本文档定义第一版桌面 Web 文明类游戏的 UI 信息架构、新手前 5 分钟引导、Tooltip、百科、回合提醒、核心面板、快捷键、可访问性和移动端预留。它承接现有技术决策：`PixiJS/WebGL` 负责地图画面，`React/DOM` 负责复杂 UI；规则修改必须通过 `Command -> Validator -> Simulation -> GameState`，UI 不直接改规则状态。

第一版 UI 目标不是做“完整文明百科”，而是让玩家在 30 回合原型里始终知道四件事：

| 问题 | UI 必须回答 |
| --- | --- |
| 我现在能做什么？ | 可行动单位、空生产队列、未选择科技、可攻击目标、可结束回合。 |
| 我为什么要这么做？ | 行动收益、资源变化、预计完成回合、胜利压力、AI 意图。 |
| 我为什么不能这么做？ | Validator 失败原因、缺少条件、移动力不足、科技前置、地块不可用。 |
| 我接下来会发生什么？ | 回合结算预览、生产/科技倒计时、敌方威胁、胜利进度。 |

## 一、UI 设计原则

| 原则 | 具体要求 | 第一版验收 |
| --- | --- | --- |
| 地图优先 | 地图永远是第一视觉层，面板不能长期遮住关键地块和单位。 | 默认布局下 16x16 地图主体可见，面板可折叠。 |
| 信息分层 | 常用信息放主界面，细节放 Tooltip，长说明放百科。 | 地块、单位、城市、科技、战斗都有两级解释。 |
| 解释规则结果 | 每个资源变化、失败操作、战斗结果都能追溯原因。 | EventLog 和 Tooltip 能解释核心数值。 |
| 行动入口明确 | 移动、生产、研究、结束回合、存档、百科入口位置固定。 | 新玩家 2 分钟内能完成第一回合。 |
| UI 不持有规则 | React 组件只展示 selector 结果并提交 Command。 | 组件内不保存单位血量、城市产出等规则状态。 |
| 失败也是反馈 | 非法操作不能静默失败。 | Validator 错误码转成可读文案和可选高亮。 |
| 少打断 | 教学和提醒嵌入回合流程，不用长篇弹窗阻断游戏。 | 教学卡片可跳过，可折叠，可从日志恢复。 |
| 可调试 | 玩家版信息透明和开发调试信息分开。 | Debug Panel 不进入普通玩家默认 UI。 |

## 二、屏幕布局表

桌面第一版默认按 16:9 到 16:10 设计，优先适配 1366x768、1440x900、1920x1080。

| 区域 | 位置 | 内容 | 交互 | 实现方式 |
| --- | --- | --- | --- | --- |
| 地图画布 | 中央全屏底层 | 地形、单位、资源、战争迷雾、选中高亮、路径预览。 | 拖拽平移、滚轮缩放、点击选择、右键移动。 | PixiJS/WebGL。 |
| 顶部状态栏 | 顶部横条 | 回合数、资源总览、当前科技、胜利压力、存档状态。 | 点击资源/科技/胜利打开对应面板。 | React/DOM。 |
| 左侧任务栏 | 左侧窄栏 | 教学任务、待处理事项、回合提醒、最近重要事件。 | 点击定位对象、展开说明、标记已读。 | React/DOM。 |
| 右侧详情面板 | 右侧抽屉 | 城市、单位、科技、外交、胜利、百科的详情面板。 | 面板切换、选择生产/科技、提交 Command。 | React/DOM。 |
| 底部行动栏 | 底部中央 | 当前选中对象可执行动作、移动/攻击/建城/跳过。 | 按钮和快捷键触发 Command。 | React/DOM。 |
| 右下回合按钮 | 右下角固定 | 结束回合、强制结束、未处理数量。 | 点击结束或打开待处理列表。 | React/DOM。 |
| Tooltip 层 | 鼠标附近或锚点旁 | 对象摘要、数值解释、失败原因、快捷帮助。 | Hover 延迟显示，按住 Alt/Shift 展开细节。 | React Portal。 |
| Toast 层 | 顶部或左下 | 科技完成、生产完成、战斗结果、存档成功/失败。 | 点击跳转到相关对象。 | React/DOM。 |
| Debug Panel | 开发模式右侧或独立浮层 | FPS、EventLog、AI 意图、Selection、Commands。 | 开关 overlay、导出 Debug、跳回合。 | React/DOM。 |

布局约束：

| 约束 | 决策 |
| --- | --- |
| 地图和 DOM 坐标 | 地块选中由 `screenToTile` 和 `UIState.hoveredTileId` 连接，DOM Tooltip 只读派生数据。 |
| 面板遮挡 | 右侧面板宽度建议 360-420px，可折叠；地图相机边界要考虑面板遮挡区。 |
| 同时打开面板 | 第一版同一时间只打开一个主详情面板，避免状态混乱。 |
| 小屏桌面 | 宽度低于 1200px 时右侧面板覆盖地图；低于 900px 时进入紧凑布局。 |

| 层级 | 典型内容 | 信息密度 | 进入方式 |
| --- | --- | --- | --- |

## 六、左侧任务与提醒

左侧任务栏分为“教学任务”和“待处理事项”。教学任务面向新玩家，待处理事项面向每一回合的操作完整性。

| 类型 | 示例 | 触发条件 | 点击行为 | 是否阻止结束回合 |
| --- | --- | --- | --- | --- |
| 教学任务 | 选择第一项科技。 | 新局前 5 分钟且未完成对应步骤。 | 打开科技面板并高亮推荐项。 | 不阻止。 |
| 必要提醒 | 还没有选择科技。 | 当前玩家 `currentResearch` 为空。 | 打开科技面板。 | 弹确认，但允许强制结束。 |
| 生产提醒 | 首都没有生产项目。 | 任一城市生产队列为空。 | 定位城市并打开城市面板。 | 弹确认，但允许强制结束。 |
| 单位提醒 | 还有 2 个单位可行动。 | 可行动单位数大于 0。 | 选中下一个可行动单位。 | 不阻止。 |
| 危险提醒 | 敌方战士接近首都。 | 敌方军事单位进入首都 4 格内且可见。 | 定位敌军和首都。 | 不阻止。 |
| 胜利提醒 | AI 科技胜利进度超过 70%。 | 胜利面板计算压力达到阈值。 | 打开胜利面板。 | 不阻止。 |
| 系统提醒 | 自动存档失败。 | Storage 返回失败。 | 打开存档面板。 | 不阻止。 |

## 七、新手前 5 分钟引导

教学目标：让玩家在不读长说明的情况下完成第一回合，理解地图、单位、城市、科技、生产和结束回合的基本关系。

| 步骤 | 预计时间 | 触发时机 | 引导文案重点 | 玩家动作 | 完成条件 | 埋点 |
| --- | ---: | --- | --- | --- | --- | --- |
| 1. 认识局面 | 0:00-0:20 | 新局加载完成 | 你有一座首都、一个侦察兵、一个战士，目标是在 30 回合内赢得征服或科技胜利。 | 点击“开始”。 | 关闭开局卡片。 | `tutorial_step_completed:intro` |
| 2. 移动侦察兵 | 0:20-1:00 | 首次可操作 | 侦察兵视野远，适合揭开战争迷雾。高亮 2-3 个推荐地块。 | 选择侦察兵并移动。 | `MOVE_UNIT` 成功且单位为侦察兵。 | `first_unit_move` |
| 3. 查看地块产出 | 1:00-1:30 | 侦察兵移动后 | 不同地形提供不同资源，Hover 地块可以看产出和移动消耗。 | Hover 或点击一个资源地块。 | 打开地块 Tooltip 超过 1 秒。 | `tooltip_opened:tile` |
| 4. 选择城市生产 | 1:30-2:30 | 首都生产队列为空 | 城市用生产力制造单位和建筑。推荐侦察兵、建造者或粮仓。 | 打开城市面板并选择生产。 | `SET_CITY_PRODUCTION` 成功。 | `first_production_chosen` |
| 5. 选择第一项科技 | 2:30-3:30 | 当前科技为空 | 科技决定长期路线。农业偏成长，采矿偏生产，侦察偏探索。 | 打开科技面板并选择科技。 | `CHOOSE_TECH` 成功。 | `first_tech_chosen` |
| 6. 结束回合 | 3:30-4:30 | 已移动至少一个单位且有生产/科技 | 结束回合后城市会结算资源，AI 会行动。 | 点击结束回合或按 `Enter`。 | `END_TURN` 成功。 | `turn_1_completed` |
| 7. 阅读结算 | 4:30-5:00 | 第 2 回合开始 | 日志会告诉你上回合发生了什么，生产和科技离完成还差多久。 | 展开回合日志或 Hover 科技条。 | 打开日志或 Tooltip。 | `event_log_opened` |

教学规则：

| 规则 | 决策 |
| --- | --- |
| 推荐而非强制 | 教学只推荐动作，不锁死玩家自由操作。 |
| 可跳过 | 每个教学卡片可跳过，跳过后仍保留待处理提醒。 |
| 可恢复 | 跳过教学后，百科中保留“快速上手”条目。 |
| 不重复打扰 | 同一教学步骤完成后不再弹出，只在左侧任务栏保留历史。 |
| 与 Command 绑定 | 教学完成条件以成功 Command 或明确 UI 行为为准，不以按钮点击为准。 |

## 九、Tooltip 规则

Tooltip 用于解释“眼前对象”，百科用于解释“系统规则”。Tooltip 内容要短、可扫读、可从规则数据派生。

| 类型 | 触发 | 内容 | 展开细节 | 相关来源 |
| --- | --- | --- | --- | --- |
| 地块 Tooltip | Hover 地块、键盘焦点 | 地形、资源、产出、移动消耗、防御加成、是否可建城。 | 显示城市范围、视野状态、不可进入原因。 | `MapState.tiles`、地形配置。 |
| 单位 Tooltip | Hover 单位或行动按钮 | 单位类型、生命值、攻击、射程、移动力、视野、维护费。 | 显示本回合可行动原因和限制。 | `UnitState`、单位配置。 |
| 城市 Tooltip | Hover 城市或顶部城市摘要 | 人口、成长进度、生产项目、每回合产出、维护。 | 显示工作地块和建筑加成来源。 | `CityState`、城市 selector。 |
| 科技 Tooltip | Hover 科技节点 | 成本、前置、解锁、预计完成回合。 | 显示已投入科技点、切换后是否保留进度。 | `TechState`、科技配置。 |
| 生产 Tooltip | Hover 生产项 | 成本、用途、前置、预计完成回合。 | 显示当前城市生产力来源。 | 城市 selector、建筑/单位配置。 |
| 战斗预览 | Hover 攻击目标 | 预计伤害、反击伤害、地形防御、攻击后状态。 | 显示公式拆解和可能击杀。 | Validator 预览、战斗配置。 |
| 按钮 Tooltip | Hover/焦点按钮 | 动作名称、快捷键、可用/禁用原因。 | 显示对应 Command 和失败码。 | UI action registry。 |
| 错误 Tooltip | 非法操作后 | 失败原因、解决方法。 | 可定位缺少条件，如前置科技或移动力。 | `ValidationResult`。 |

Tooltip 展示规范：

| 项目 | 规则 |
| --- | --- |
| 显示延迟 | 普通 Hover 300ms 后显示；错误 Tooltip 立即显示。 |
| 位置 | 优先靠近鼠标或焦点对象，不能超出视口；靠右面板时自动翻转。 |
| 长度 | 默认 3-8 行；超过 8 行时只显示摘要和“查看百科”。 |
| 数值格式 | 统一显示 `当前 / 目标`、`+每回合`、`预计 N 回合`。 |
| 禁用动作 | 禁用按钮必须给出原因，不只变灰。 |
| 键盘访问 | 按钮获得焦点时也能显示 Tooltip；`Esc` 关闭。 |
| 进阶展开 | 按住 `Alt` 或点击“详情”显示公式拆解。 |

## 十一、百科条目分类

百科是系统说明中心，用 React/DOM 实现，支持搜索、分类、从 Tooltip 深链跳转。

| 分类 | 条目 | 第一版内容范围 |
| --- | --- | --- |
| 快速上手 | 第一回合、移动、生产、科技、结束回合。 | 5 分钟教学的文字版。 |
| 地图与地形 | 平原、森林、丘陵、河流、山脉、水域、战争迷雾。 | 产出、移动、防御、可建城、可通行。 |
| 资源 | 粮食、生产力、金币、科技。 | 局部/全局属性、来源、用途、负金币惩罚。 |
| 城市 | 人口、成长、工作地块、维护、生产队列、城市生命值。 | 公式和示例。 |
| 建筑 | 粮仓、工坊、市场、学院、城墙。 | 成本、效果、前置、适合路线。 |
| 单位 | 侦察兵、战士、建造者、弓手。 | 属性、用途、维护、克制关系。 |
| 科技 | 农业、采矿、侦察、弓术、工具、书写、贸易、石工、战术、工程、数学、天文台计划。 | 成本、前置、解锁、路线意义。 |
| 战斗 | 近战、远程、反击、地形防御、城市占领。 | 伤害公式、示例、常见失败原因。 |
| 外交与 AI | 关系状态、战争状态、AI 意图。 | 第一版只解释轻量外交和可见意图。 |
| 胜利 | 征服、科技、分数。 | 触发条件、进度查看、分数公式。 |
| 操作 | 鼠标、滚轮、快捷键、面板入口。 | 完整快捷键表和输入说明。 |
| 存档与设置 | 自动存档、手动存档、读档、设置。 | 存档范围、失败提示、版本兼容提示。 |

百科条目结构：

| 字段 | 说明 |
| --- | --- |
| 标题 | 简短名词，如“粮食”或“征服胜利”。 |
| 摘要 | 1-2 句话说明用途。 |
| 规则 | 公式、限制和结算时机。 |
| 示例 | 至少一个第一版数值例子。 |
| 相关条目 | 可跳转到科技、建筑、单位或胜利。 |
| 数据来源 | 对应配置 ID，便于未来从配置生成。 |

## 十二、回合提醒

结束回合按钮需要同时承担操作入口和状态诊断，不应该只是一个普通按钮。

| 状态 | 按钮表现 | 点击后行为 |
| --- | --- | --- |
| 可安全结束 | 高亮显示“结束回合”。 | 直接提交 `END_TURN`。 |
| 有轻量未处理项 | 显示角标，如 `2`。 | 打开确认 Popover，列出可行动单位或待处理事项。 |
| 缺关键选择 | 显示警告色，如未选择科技或空生产队列。 | 先展示待处理列表，二次确认可强制结束。 |
| AI/结算中 | 显示“结算中”。 | 禁用按钮，展示进度和可取消项仅限开发模式。 |
| 胜利已触发 | 显示“查看复盘”。 | 打开复盘面板。 |

待处理检查表：

| 检查项 | 严重度 | 提醒文案 | 点击行为 |
| --- | --- | --- | --- |
| 未选择科技 | 高 | `没有正在研究的科技。` | 打开科技面板。 |
| 城市无生产 | 高 | `首都没有生产项目。` | 定位城市并打开城市面板。 |
| 单位可行动 | 中 | `还有 2 个单位可行动。` | 选中下一个可行动单位。 |
| 可攻击目标 | 中 | `有 1 个敌方单位在射程内。` | 定位单位并显示攻击预览。 |
| 金币将为负 | 中 | `结束后金币可能为负，生产力会受惩罚。` | 打开经济摘要。 |
| 科技/生产即将完成 | 低 | `农业将在本回合后完成。` | Hover 展示解锁内容。 |

## 十三、城市面板规格

| 区块 | 内容 | 交互 |
| --- | --- | --- |
| 标题区 | 城市名、归属、人口、生命值、防御力。 | 定位城市，重命名第二版预留。 |
| 成长区 | 粮食库存、成长阈值、预计成长回合、粮仓影响。 | Tooltip 展示成长公式。 |
| 产出区 | 粮食、生产力、金币、科技每回合产出。 | 展开查看城市中心、工作地块、建筑来源。 |
| 工作地块 | 当前人口自动工作的 N 个地块。 | Hover 高亮地图地块。 |
| 生产队列 | 当前项目、已投入、成本、预计完成、溢出提示。 | 选择/切换生产项。 |
| 建筑区 | 已有建筑、可建建筑、未解锁建筑。 | Hover 显示效果和前置科技。 |
| 维护区 | 城市维护、距离维护、单位维护摘要。 | 打开经济 Tooltip。 |

城市面板要特别解释“粮食/生产力是城市局部，金币/科技偏全局”，避免玩家误以为所有城市共享生产力。

## 十四、科技面板规格

| 区块 | 内容 | 交互 |
| --- | --- | --- |
| 当前研究 | 科技名、进度、每回合科技收入、预计完成。 | 点击定位科技节点。 |
| 科技树 | 8-12 个科技节点，显示前置和分支。 | 点击选择可研究科技。 |
| 解锁预览 | 单位、建筑、规则、胜利项目。 | Hover 查看对应百科。 |
| 路线标签 | 成长、生产、探索、军事、经济、科研。 | 可作为筛选，不影响规则。 |
| 已完成 | 完成时间和带来的关键变化。 | 展开历史。 |

科技节点状态：

| 状态 | 表现 | Tooltip |
| --- | --- | --- |
| 已完成 | 明确完成标记。 | 显示完成回合和解锁内容。 |
| 正在研究 | 进度条。 | 显示预计完成回合和每回合科技来源。 |
| 可研究 | 普通可点击。 | 显示路线意义和成本。 |
| 前置不足 | 灰显但可 Hover。 | 显示缺少哪些前置。 |
| 胜利项目 | 特殊边框。 | 显示科技胜利进度。 |

## 十五、胜利面板规格

| 胜利 | 展示内容 | 玩家要能理解的问题 |
| --- | --- | --- |
| 征服胜利 | 双方首都位置、首都生命值、最近敌军距离、战争状态。 | 谁离攻破首都更近？我需要什么单位？ |
| 科技胜利 | 数学科技状态、天文台计划进度、双方科技完成数。 | 谁更接近科技胜利？我还能追上吗？ |
| 分数胜利 | 城市、人口、科技、单位、金币、首都伤害、科技项目得分。 | 第 30 回合如果结束，谁会赢，为什么？ |

复盘面板必须列出胜负原因：

| 模块 | 展示 |
| --- | --- |
| 胜利类型 | 征服、科技或分数。 |
| 关键节点 | 第几回合建第二城、首次战斗、完成关键科技、占领首都。 |
| 分数拆解 | 双方每项分数对比。 |
| 改进提示 | 只给规则事实，如“你有 4 回合没有研究科技”，避免评价玩家。 |

## 十六、外交面板规格

第一版外交是轻量系统，重点是“AI 为什么这样做”和“战争状态是否清楚”，不做复杂交易市场。

| 区块 | 内容 | 第一版范围 |
| --- | --- | --- |
| AI 概览 | AI 名称、首都状态、已知城市数、当前可见单位。 | 可见信息和半公开摘要。 |
| 关系状态 | 中立、紧张、战争。 | 三档即可。 |
| 关系原因 | 抢地、接近边境、军力差距、科技压力、宣战记录。 | 从 AI Intent 和 EventLog 派生。 |
| AI 意图 | 探索、扩张、防守、进攻、科研。 | 显示最近一条主要意图和置信度。 |
| 战争操作 | 宣战、查看战争影响。 | `DECLARE_WAR`；停战第二版预留。 |
| 交易预留 | 金币、开放边境、停战。 | 第一版只显示“第二版预留”。 |

外交信息透明规则：

| 场景 | 展示要求 |
| --- | --- |
| AI 宣战 | 显示直接原因，例如“你的战士接近 AI 首都，且军力弱于 AI”。 |
| AI 扩张 | 显示“AI 正在寻找第二城位置”，不必公开完整地图坐标。 |
| 关系下降 | EventLog 记录原因和数值变化。 |
| 玩家宣战 | Tooltip 显示可能影响：进入战争状态、可攻击单位和城市。 |

## 十七、快捷键表

快捷键第一版服务桌面 Web，不要求复杂自定义，但必须避免和浏览器常用快捷键冲突。

| 快捷键 | 动作 | 作用域 | 备注 |
| --- | --- | --- | --- |
| `Enter` | 结束回合或确认结束回合。 | 全局，输入框外。 | 有未处理事项时先打开确认。 |
| `Space` | 选中下一个可行动单位。 | 地图/全局。 | 无可行动单位时提示。 |
| `Esc` | 关闭 Tooltip、Popover、当前面板或取消选择。 | 全局。 | 逐层关闭。 |
| `T` | 打开/关闭科技面板。 | 全局。 | 对应 `CHOOSE_TECH` 入口。 |
| `C` | 打开当前选中城市面板。 | 有选中城市或城市列表。 | 无城市选中时打开城市列表。 |
| `V` | 打开胜利面板。 | 全局。 | 查看胜利压力。 |
| `D` | 打开外交面板。 | 已遇见 AI 后。 | 未遇见时显示说明。 |
| `L` | 打开回合日志。 | 全局。 | 定位最近事件。 |
| `F1` | 打开百科。 | 全局。 | 浏览器拦截时提供 UI 按钮。 |
| `S` | 手动存档。 | 全局，输入框外。 | 不使用 `Ctrl+S` 覆盖浏览器。 |
| `+` / `-` | 地图缩放。 | 地图焦点。 | 滚轮替代方案。 |
| 方向键 / `WASD` | 平移地图。 | 地图焦点。 | 输入框内禁用。 |
| `Alt` 按住 | Tooltip 展开公式。 | Tooltip 显示时。 | 用于进阶解释。 |
| `F3` | Debug Panel。 | 开发模式。 | 正式试玩版本可隐藏。 |

## 十九、信息透明规则表

| 系统 | 必须透明的信息 | 可以隐藏或延后 |
| --- | --- | --- |
| 地图 | 已探索地形、当前可见单位、地块基础产出、移动消耗。 | 未探索区域、不可见敌军。 |
| 城市 | 自己城市的全部产出、成长、生产、维护。 | AI 未侦察城市的完整产出。 |
| 科技 | 自己科技树、成本、前置、解锁、预计完成。 | AI 当前研究可半公开，只展示路线倾向。 |
| 战斗 | 攻击前预计伤害、反击、地形防御、攻击后消耗。 | 可保留少量随机波动，但第一版建议固定伤害。 |
| 外交 | 战争状态、关系变化原因、AI 当前大方向。 | AI 的完整评分表只进 Debug。 |
| 胜利 | 双方征服/科技/分数进度。 | AI 隐藏地图上的未发现城市细节。 |
| 资源 | 每回合收入、支出、净变化和来源。 | 不需要展示内部小数的全部精度，只在详情中说明。 |

## 二十、错误与空状态

| 场景 | UI 处理 |
| --- | --- |
| Validator 返回失败 | 不改变状态，展示错误 Tooltip，EventLog 记录 `command_rejected`。 |
| 面板无对象 | 显示空状态和下一步建议，例如“选择一座城市查看生产”。 |
| 科技无可选项 | 显示原因，通常是所有可研究项已完成或配置错误；开发模式提示检查配置。 |
| 存档失败 | Toast + 存档面板详情，保留可导出 Debug 的入口。 |
| WebGL context lost | 地图区域显示恢复中，DOM UI 保持可见，Debug 记录错误。 |
| Worker 超时 | UI 显示 AI 思考超时，第一版可降级主线程简单 AI。 |

## 二十一、可访问性

| 方向 | 第一版要求 |
| --- | --- |
| 键盘操作 | 主要面板可用键盘打开、关闭、切换焦点；地图至少提供方向键平移和快捷键选择下一个单位。 |
| 焦点状态 | DOM 按钮、面板、Tooltip 触发元素都有明显焦点样式。 |
| 色彩冗余 | 资源、阵营、警告不能只靠颜色区分，需要图标、文字或纹理辅助。 |
| 字号 | 主界面正文不低于 14px，Tooltip 不低于 13px，关键数值不低于 16px。 |
| 对比度 | 面板正文和按钮文字保证足够对比度；地图上小字只用于调试或次要信息。 |
| 动效控制 | 设置中提供减少动效选项，关闭非必要动画和闪烁。 |
| Tooltip 可达 | 键盘焦点可以触发 Tooltip，移动鼠标不是唯一方式。 |
| 屏幕阅读器预留 | 核心 DOM 面板使用语义按钮、列表、标题；Canvas 地图提供选中对象的文本摘要。 |

## 二十二、移动端预留

第一版不以手机为主，但布局和输入不要把未来移动适配堵死。

| 方向 | 第一版预留 |
| --- | --- |
| Pointer Events | 鼠标、触控、触控笔统一走 Pointer Events 抽象。 |
| 面板布局 | 右侧面板可变成底部抽屉，避免小屏无法阅读。 |
| Tooltip | 移动端 Hover 不存在，预留点击/长按显示详情。 |
| 相机 | 预留双指缩放和单指拖拽，不在规则层依赖鼠标事件。 |
| 按钮尺寸 | 关键操作按钮最小点击区域不低于 40px，移动端可放大到 44px。 |
| 快捷键替代 | 所有快捷键动作必须有可点击 UI 入口。 |
| UI 密度 | 科技树、城市面板、胜利面板要能折叠分组，未来适配窄屏。 |

## 二十三、React/DOM 与 GameState 边界

| UI 行为 | 正确做法 | 禁止做法 |
| --- | --- | --- |
| 展示城市产出 | 从 selector 读取 `GameState` 并派生展示。 | 在组件本地重新计算一套不一致公式。 |
| 选择生产 | 提交 `SET_CITY_PRODUCTION`。 | 直接修改 `city.productionQueue`。 |
| 选择科技 | 提交 `CHOOSE_TECH`。 | 直接写 `tech.currentResearch`。 |
| 结束回合 | 先做待处理检查，再提交 `END_TURN`。 | UI 自己增加回合数。 |
| Tooltip 失败原因 | 展示 `ValidationResult` 的 code/message。 | 用硬编码猜测失败原因。 |
| 教学完成 | 监听成功 Command 或 UI 行为事件。 | 只根据按钮点击判定完成。 |
| 面板展开 | 写入 `UIState.openPanel`。 | 写入存档中的 `GameState.phase`。 |

## 二十六、推荐实现顺序
