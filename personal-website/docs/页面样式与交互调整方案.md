## 1. 设计目标与视觉方向

设计目标是让访客读懂身份、理解案例中的个人工作、顺畅阅读记录并找到联系方式。视觉应服务“有事实、有职责、有过程”的内容，让中文长标题、业务说明和真实截图成为主体。

### 1.1 三种方向比较

| 方向 | 优点 | 约束 | 决定 |
|---|---|---|---|
| 暖白纸面、深色文字、陶土强调、简洁工程排版 | 延续当前风格；中文阅读舒适；案例与记录协调 | 需要控制暖色面积与弱文字对比度 | 推荐 |
| 冷灰蓝、密集仪表盘式卡片 | 强调工具与系统感 | 容易把个人内容站做成后台，长文阅读分散 | 不作为主方向 |
| 全黑大字、强动效作品展示 | 视觉冲击强 | 对截图、动画资源要求高；阅读和性能成本更高 | 不作为首期主方向 |

推荐保留温暖和深浅主题，减少大范围玻璃模糊、逐字播放和反复入场。页面重点以排版、真实案例图、流程图和分隔关系形成，不用所有模块都放进大圆角卡片。

不自动生成仿真的客户系统截图、客户评价或真人头像作为作品证据。素材不全时也要有完整可用的纯文本版式。

### 1.2 首页内容权重

1. 第一层：姓名、角色、两行定位、查看案例。
2. 第二层：三个代表案例及各自个人职责。
3. 第三层：可承担工作与工作方式，分别由案例支撑。
4. 第四层：最近技术记录，用紧凑列表呈现。
5. 结束入口：直接联系与沟通信息。

技术标签、AI工具名称、教育经历和版权信息均不与首屏身份、代表项目争夺视觉权重。首页只设一个主要行动“查看案例”，联系为次要行动；下方结束区再强化联系。

状态色不作为唯一信息来源：选中有形状/文字/语义，失败有说明，项目交付状态有准确文本。

### 3.2 对比度计算与限制

按sRGB相对亮度公式计算纯色对比度：(较亮L+0.05)/(较暗L+0.05)。下表为声明色数学计算，不含透明叠加、图片背景、悬停或实际字体渲染。

| 组合 | 计算值约 | 结论 |
|---|---:|---|
| 现有白字 / #D89368深色主按钮 | 2.53:1 | 不足以满足普通文字4.5:1目标 |
| 现有白字 / #B05A36浅色主按钮 | 4.81:1 | 此纯色组合达到普通文字目标 |
| 现有#B05A36链接 / #F7F0E4背景 | 4.25:1 | 此纯色组合低于普通文字目标，实际落点需核对 |
| 建议#202620正文 / #F7F5EF | 14.17:1 | 候选纯色通过 |
| 建议#596258次字 / #F7F5EF | 5.81:1 | 候选纯色通过 |
| 建议#A14D2C链接 / #F7F5EF | 5.33:1 | 候选纯色通过 |
| 建议白字 / #A14D2C按钮 | 5.81:1 | 候选纯色通过 |
| 建议#EDF1E8正文 / #151915 | 15.53:1 | 候选纯色通过 |
| 建议#B6C0B0次字 / #202720 | 8.13:1 | 候选纯色通过 |
| 建议#E0A27C链接 / #151915 | 8.15:1 | 候选纯色通过 |
| 建议#21170F按钮字 / #E0A27C | 8.06:1 | 候选纯色通过 |
| 建议浅色控件边框 / 白表面 | 3.79:1 | 仅证明此边界组合，仍需检查周边 |
| 建议深色控件边框 / #202720 | 3.87:1 | 仅证明此边界组合，仍需检查周边 |

普通文本以4.5:1为验收目标，大字按适用定义至少3:1；不要把所有标题都默认当大字，也不能四舍五入临界值为通过。正式验收需要覆盖真实合成背景与各交互状态。[W3C对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

| 主要断点 | 768px、1024px；320/390/1440用于验证，不为每种设备另设规则 |
| 栅格间距 | 手机16px、平板20px、桌面24px |

| 间距序列 | 4、8、12、16、24、32、48、64、96px |
| 区块垂直间距 | 手机48–64px、桌面64–96px |
| 圆角 | 控件8px、图片12px、卡片16px、标签999px |
| 控件建议触达区 | 最低44×44px；图标可18–20px，扩大外层可点击范围 |

44×44是本站舒适触达目标，不将它误写成所有场景通用的WCAG AA最低值。断点以内容不挤压为依据；768附近如果导航仍放不下，可在样板验证后调整一次，并记录原因。

背景由页面壳统一控制；阅读区不重复铺大面积不透明背景。只在确有容器关系时加边框或卡片，不给每个段落加阴影。

## 5. 导航、主题与关键交互

### 5.1 桌面导航

- 顺序：首页、项目、技术记录、关于、联系；页脚放skills兼容入口及法律/地图入口。
- 文章详情属于技术记录栏目、案例详情属于项目栏目。完全匹配页面使用aria-current=page；详情时栏目可用视觉高亮与适用的location语义，不把列表链接谎称为当前详情页本身。
- 添加键盘可见的“跳到主要内容”。固定头部不遮挡锚点标题，scroll-margin-top与header-height联动。
- 滚动后只轻微改变边框/背景，不缩放文字、不改变页面排版高度。
- 头部初次加载即可见，不让用户等待首次访问入场动画。

### 5.2 手机导航：首期采用展开式导航

首期推荐在头部下方展开的普通导航面板，避免为几个链接引入不必要的全屏模态复杂度。

1. 触发器用button，Enter/Space可开关，aria-expanded与aria-controls同步。
2. 关闭时内部链接不在Tab顺序中；打开后保持正常文档焦点顺序。
3. Escape关闭并恢复到触发按钮；点击导航完成跳转后关闭。
4. 切到桌面断点时清理小屏状态；页面离开时清理副作用。
5. 面板不阻断背景时不要设置aria-modal，不强制焦点陷阱，也不默认锁body滚动。
6. 禁JavaScript时仍应提供可用导航降级，例如首屏可访问的基础链接或原生details方案，不能留下永远关着的菜单。

展开组件采用按钮与状态表达。[W3C Disclosure模式](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)

若样板选择覆盖整屏的模态导航，则改用完整dialog模型：焦点进入、循环Tab、Escape、背景不可交互、可见关闭按钮、关闭后焦点恢复，并保存/恢复原始滚动状态。两种模式只能选一种实现，不能外观像模态而缺行为。[W3C Dialog模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

### 5.3 主题策略

- preference为system/light/dark，resolvedTheme为light/dark。
- 没有手动选择时按system解析；不能把第一次自动解析出的dark写成手动dark偏好。
- 初始脚本、provider和UI用同一决策规则，避免三个位置争相设置主题。
- localStorage读取或写入失败时页面仍可浏览，当前页仍能临时切换。
- 主题选择器显示明确文字或可访问名称；不能只显示没有说明的太阳/月亮。
- 第一次加载、刷新、路由切换、浏览器返回和系统主题变化都需要验证。
- 无JS时至少提供可读的默认/系统主题CSS，不让核心正文依赖脚本。

### 5.4 搜索、分类与复制

搜索保留标题/摘要/标签范围。新增可见或辅助label、清空按钮、结果计数；清除输入不强制清除分类，另提供“重置全部筛选”。选择分类用aria-pressed，选中同时有边框/标记而非仅颜色。

建议将博客query/category同步到URL查询参数，列表返回时恢复；参数在客户端读取，不影响静态路径生成。初次水合后恢复状态需测试，不把静态构建变成请求时渲染。只有4篇内容，无须服务端检索和分页。

联系页“打开邮件”和“复制邮箱”是不同动作。复制成功显示短反馈；权限或环境失败时提示手动选择文本，不显示发送成功。操作反馈可用温和的aria-live，不持续播报每个输入字符。

## 6. 逐页布局与调整

线框表达信息顺序，不是已生成设计稿。桌面左右栏在窄屏按DOM顺序堆叠，不用CSS视觉重排制造键盘阅读顺序差异。

### PG01 首页

**目的**：让访客先认识身份，再用真实项目判断能力。


### PG02 项目列表

**目的**：便于扫描和选择，不在列表展示全部案例长文。

### PG04 技术记录列表

标题与简短说明 → 搜索label/输入框 → 分类与结果数 → 文章列表。

无匹配显示“没有找到匹配记录”，保留关键词输入并提供重置；不要把无结果当异常弹窗。搜索和分类切换不自动跳到页顶，不造成焦点丢失。

### PG05 文章详情

返回/面包屑 → 标题 → 发布/修订日期与分类 → 摘要（不机械重复正文首段）→ 正文 → 相关项目。

- 正文H1来自页面标题。编辑规范要求正文从H2开始；迁移时只移除与标题相同的首个H1，不全局丢弃合法正文标题。
- 当正文有至少3个有效H2且确有导航价值时显示目录，此阈值为编辑建议。
- 当前4篇没有代码展示需求；遇到代码内容再启用构建时高亮和复制，不加载无用途的全局高亮脚本。
- 表格、pre放在局部横向滚动区；长链接换行；表格的标题/上下文使滚动内容可理解。
- 图片、代码、引用和列表共享Prose样式；不让旧Prism CSS与新代码主题重复控制同一属性。
- 文章标题和旧URL保持映射，显示名称修改不能丢失旧链接。

### PG06 关于

桌面：个人概述 → 经历与案例主栏 + 次级能力/联系侧栏 → 教育。手机：概述 → 重要经历 → 对应案例 → 能力 → 教育 → 联系。

能力以“做过什么”表达，例如复杂表单、多端页面、同步故障排查、接口/数据库联调，并给案例链接。取消技能星级和没有方法依据的百分比。

每段经历显示真实角色、单位/项目、时间与职责，不自动填补2025.01之后的任职空白。没有头像时采用姓名排版，页面仍完整。每页只有一个main，经历内部使用section。

### PG07 联系

桌面两栏：左侧合作范围与直接联系，右侧“沟通前提供什么”。手机先显示联系方式与动作，再显示材料清单。

- 主动作“打开邮件”，次动作“复制邮箱”；GitHub作为补充。
- 材料清单可包括项目类型、当前状态、主要问题、时间要求；这是联系说明，不是没有后端的输入表单。
- 长邮箱自然换行或可选择复制，不能用省略号隐藏核心信息。
- 二维码资源未就绪时不显示；不新增未经确认的手机号、联系方式或接单承诺。
- 邮件客户端未配置时，复制文本作为可用替代。复制失败反馈不能说消息已发送。

### PG08 技能兼容页

首期保留/skills/，使用与关于一致的能力组及案例链接，避免维护第二套能力数据和技能百分比。主导航不必增加技能项。若后续合并到关于页，按总体方案的宿主兼容策略处理旧路径，本样式方案不假定存在301。

### PG09 隐私与条款

共用阅读容器与Prose，标题 → 真实修订日期 → 章节正文 → 联系入口。正文与实际功能一致；不因视觉重构凭空增加分析服务、账户或在线表单相关承诺。

修订日期是内容字段；长链接换行；只有文本足够长时才显示目录，不用每次当前日期制造更新。

### PG10 HTML网站地图

简单分组链接：主要页面、案例、技术记录、说明页。桌面可分2列，手机1列。每个公开条目有稳定标题，不重复主菜单同一路径。它为人提供导航，机器XML sitemap由总体架构单独生成。

### PG11 404与异常降级

标题“页面未找到” → 简短说明 → 返回首页/查看项目/技术记录。保持导航和主题基本一致，避免大型动画和自动跳转掩盖404。

静态宿主必须验证未知路径的真实返回行为；页面长得像404不等于HTTP状态正确。缺失图片保留图注与替代文字，不使整张案例卡消失；构建期缺内容应在检查时失败，不把所有错误伪装成“暂无内容”。

| 详情说明图 | 每案例0–3张，图注说明展示内容与职责 | 使用步骤列表/简洁流程说明 |
| 头像 | 可选真实照片 | 姓名与角色排版 |
| 社交分享图 | 统一标题模板，候选1200×630 | 构建时文本模板，不能冒充成果截图 |

尺寸是输出建议，不要求为每个位置生成所有尺寸。图片使用适合内容的WebP/AVIF或清晰PNG，优先保证界面截图文字可读。展示图可以裁切到约16:10，但内容证据图应保持原比例；裁切不能删掉关键状态信息。

为素材记录来源、公开范围、alt、图注、尺寸。首屏关键图避免被延迟到很晚，其余图按浏览器能力延迟加载；固定尺寸降低布局跳动。素材体积预算以R1实测与清晰度折中确定，不把一个压缩数值强套所有截图。

公开版本与原始客户资料分开，构建只读公开目录；不将原图、聊天记录和客户资料一起打进静态目录。源码未使用的二维码地址不能作为存在有效二维码的证据。

## 8. 动效、可访问性与失败状态

### 8.1 动效规则

- 默认状态反馈120–180ms；展开180–240ms；位移不超过8px。
- 不让主要正文等待打字机、动画结束、IntersectionObserver触发才能阅读。
- 删除首页显著的无限循环、长期will-change和全局按钮抬起；只有测量证明需要时才做局部渲染优化。
- prefers-reduced-motion启用时关闭位移、逐字显示、顺序入场和平滑滚动；导航与焦点行为保留。
- 背景和装饰层不占据可点击内容上方，不遮挡焦点和文本选择。

### 8.2 状态矩阵

| 对象 | 必测状态 | 通过条件 |
|---|---|---|
| 导航 | 当前页/子栏目、手机开关、跨断点 | 名称与状态准确；键盘可达；不留滚动锁 |
| 主题 | 首访、系统、手动、存储拒绝、刷新 | 正文可读；偏好一致；存储失败不崩溃 |
| 筛选 | 全部、选中、组合、清空 | 选中可见且有语义，返回列表状态可恢复 |
| 搜索 | 空白、中文、大小写、无匹配 | label明确，清空动作可用，不丢焦点 |
| 卡片 | 无图、长标题、很多标签、无外链 | 不嵌套链接，不遮挡内容，不留空按钮 |
| 正文 | 长URL、宽表、代码、引用、长中文标题 | 页面本体不横向溢出，局部滚动可用 |
| 复制 | 成功、权限拒绝、不支持 | 清楚反馈，失败提供可选择文本 |
| 内容 | 无匹配、尚无发布、未知ID | 不同情况有不同说明与正确导航 |
| 资源 | 字体失败、图片失败、脚本延迟/禁用 | 核心内容可读，导航有降级，布局不坍塌 |
| 缩放 | 200%文字缩放、320CSS像素回流 | 内容和操作不丢失；二维内容可合理局部滚动 |

回流依据WCAG解释按320CSS像素检查；这与“手机截图看起来没问题”不同。宽表和代码等二维内容可局部滚动，但不能用全页裁切隐藏信息。[W3C回流说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

## 9. 样式代码收敛与迁移

建议层次：

~~~text
tokens.css：主题、字号、间距、宽度、边界、层级
    ↓
globals.css：reset、body、基础焦点与媒体规则
    ↓
PageShell / Prose / UI组件：共享语义和状态
    ↓
页面CSS Modules：仅页面独有布局
~~~

实施顺序：

1. 建立tokens及基础色/字/间距示例，复核对比度。
2. 重做PageShell、Header、Footer、ThemeControl，保证一个main与稳定导航。
3. 以首页和一个案例详情验证展示/阅读两种布局。
4. 将项目/记录列表、文章、关于/联系/说明页迁移到相同组件。
5. 逐组件检查旧CSS和依赖引用后清理，避免先删除再寻找使用位置。

旧组件处理：

| 旧内容 | 建议 |
|---|---|
| Tagline代码装饰与Typewriter | 首期撤出关键内容路径；无引用后再删除 |
| MainContent多套hidden/visible/stable | 收敛为默认可见区块与可选轻动效 |
| Header未渲染搜索逻辑和CSS | 引用确认后删除；搜索保留在记录页 |
| Footer多列motion展开 | 首期简化链接布局，确有必要再使用语义折叠 |
| sections/Contact旧表单 | 不作为联系页重构基线，无引用后删除残留 |
| ScrollAnimation | 无引用则删除，不为保留组件人为增加动画 |
| 重复容器、字号、断点 | 映射到公共token，保留必要且有记录的局部例外 |
| Prism CSS与文章pre/code样式 | 按最终高亮方案单一管理 |
| 不存在的styles类名 | 逐个删除无意义引用或补明确样式，不批量猜测 |
| overflow-x:clip | 定位实际溢出原因，不能作为通过响应式检查的手段 |

## 12. 交付完成定义

页面样式调整完成需要同时满足：

- 两种主题、三档容器、统一字号与公共组件已落地。
- PG01–PG11的实际首期路由均有对应页面或明确兼容处理。
- 列表、阅读、联系、404及无素材状态都完整成立。
- V01–V12有结果记录，失败项得到修复或明确缩减实际功能范围。
